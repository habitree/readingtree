## 1. 앱 기준 URL과 하드코딩된 도메인

로그인 후 **리다이렉트되는 주소**는 `getAppUrl()`이 반환하는 값으로 결정됩니다.  
이 함수 안에 **이전 도메인이 기본값으로 하드코딩**되어 있으면, Vercel 프로젝트/도메인을 바꿔도 **로그인 후에만 이전 도메인으로 이동**하는 현상이 발생할 수 있습니다.

---

## 2. 해당 스크립트 파일 위치

| 항목 | 내용 |
|------|------|
| **파일 경로** | `lib/utils/url.ts` |
| **함수** | `getAppUrl()` |
| **사용처** | `app/actions/auth.ts`(OAuth `redirectTo`), `app/callback/route.ts`(콜백 후 리다이렉트) |

---

## 3. 하드코딩된 도메인이 있는 위치 (확인용)

아래는 **이전 도메인** `https://readingtree.vercel.app` 이 그대로 들어 있는 **기본값(fallback)** 입니다.  
`NEXT_PUBLIC_APP_URL`·`VERCEL_URL` 등이 없거나 조건을 만족하지 않을 때 이 값이 사용됩니다.

| 행 번호 | 조건 | 코드 |
|--------|------|------|
| **66–67** | `VERCEL`이 있고 `VERCEL_ENV === "production"` 일 때, `VERCEL_URL` 없음 | `return "https://readingtree.vercel.app";` |
| **71–72** | `VERCEL`이 있고 Preview 환경일 때 | `return "https://readingtree.vercel.app";` |
| **76–78** | `VERCEL`이 없지만 `VERCEL_ENV === "production"` 일 때(이중 체크) | `return "https://readingtree.vercel.app";` |
| **122–123** | 그 외 모든 경우(맨 마지막 fallback) | `return "https://readingtree.vercel.app";` |

---

## 4. 확인 방법

### 4.1 코드에서 하드코딩 위치 찾기

프로젝트 루트에서:

```bash
# readingtree.vercel.app 이 들어 있는 파일·행 찾기
rg "readingtree\.vercel\.app" --type-add 'code:*.{ts,tsx,js,jsx}' -t code
```

또는 해당 파일만 열어서 위 표의 행 번호(66–67, 71–72, 76–78, 122–123)를 확인합니다.

### 4.2 실제로 어떤 URL이 쓰이는지 확인 (Vercel 로그)

- Vercel Dashboard → 해당 프로젝트 → **Deployments** → 최신 배포 → **Functions** 또는 **Logs**
- 로그인 시도 후 `/callback` 요청 시 `[getAppUrl]` 로그 확인:
  - `NEXT_PUBLIC_APP_URL 사용: ...` → 환경 변수로 설정한 URL 사용 중
  - `VERCEL 환경에서 VERCEL_URL 사용: ...` → Vercel이 준 URL 사용 중
  - `기본값 사용 (프로덕션 URL)` → **하드코딩된 이전 도메인** 사용 중

## 5. Vercel 프로젝트/도메인 변경 시 처리 방법

1. **환경 변수로 새 도메인 고정 (권장)**  
   - 새 Vercel 프로젝트의 **Environment Variables**에  
     `NEXT_PUBLIC_APP_URL` = **새 도메인**(예: `https://새프로젝트.vercel.app`)  
   - Production·Preview 모두 설정 후 **재배포**.  
   - 그러면 `getAppUrl()`이 1순위로 이 값을 쓰므로 하드코딩 fallback으로 가지 않습니다.  
   - 자세한 체크리스트: [06-check-and-change.md - Vercel/도메인 변경](06-check-and-change.md#vercel--도메인-변경)

2. **Supabase·OAuth 설정**  
   - Supabase **Authentication** → **URL Configuration**: Site URL·Redirect URLs에 **새 도메인** 및 `/callback` 반영  
   - 카카오/구글 개발자 콘솔의 Redirect URI에 새 도메인 기반 콜백 URL 추가  
   - 참고: [01-auth.md](01-auth.md), [06-check-and-change.md](06-check-and-change.md)

3. **코드 수정 (선택)**  
   - `lib/utils/url.ts`에서 `"https://readingtree.vercel.app"` 를 반환하는 4곳을 제거하거나,  
     `VERCEL_URL`이 있으면 `https://${VERCEL_URL}` 을 쓰고 없을 때만 기본값을 쓰도록 변경  
   - 새 프로젝트/리전을 자주 바꾸는 경우, 하드코딩을 제거해 두면 같은 문제 재발을 줄일 수 있습니다.
