# ReadTree 행동과학 기반 UX 감사 보고서

> **기준일**: 2026-03-24
> **참조 아티클**: "매일 쓸 것 같다던 그 기능, 왜 아무도 안 썼을까?" (김태길, 요즘IT, 2026-03-23)
> **목적**: 사용자의 말과 행동 불일치를 전제로 ReadTree의 기능별 마찰 포인트를 진단하고 행동과학 기반 개선안을 제시

## Executive Summary

ReadTree는 독서 기록, 서재 관리, AI 분석, 게이미피케이션 등 풍부한 기능을 갖추고 있으나, 핵심 루프(독서 기록 작성)까지의 **마찰이 크고**, 보상이 **지연형에 치우쳐** 있으며, **손실회피 프레이밍이 거의 미활용** 상태다.

## 1. 분석 프레임워크 — 5가지 행동과학 원칙

아티클에서 제시한 5가지 행동과학 해석 도구를 ReadTree 맥락에 맞게 정의한다.

### 1.1 최소 노력의 법칙 (Law of Least Effort)

**원리**: 사용자는 가장 쉬운 경로를 선택한다. 단계가 하나만 추가되어도 이탈률이 급증한다.

**ReadTree 맥락**: "기록하고 싶다" → 실제 저장까지 몇 단계가 필요한가? 각 단계에서 판단을 요구하는가?

### 1.2 인지 부하 최소화 (Cognitive Load Reduction)

**원리**: 읽기, 판단, 기억, 비교의 비용을 피하려 한다. 한 화면에 정보가 많으면 아무것도 처리하지 않는다.

**ReadTree 맥락**: 폼 필드 수, 선택지 개수, 화면 전환 횟수가 적절한가?

### 1.3 기본값 효과 (Default Effect)

**원리**: 사람은 설정을 잘 바꾸지 않는다. 기본값이 곧 제품의 가장 강력한 추천이다.

**ReadTree 맥락**: 온보딩 직후의 기본 상태가 사용자의 실제 행동 패턴을 반영하는가?

### 1.4 현재 편향과 지연된 보상 (Present Bias & Delayed Reward)

**원리**: 먼 미래의 이득보다 지금의 귀찮음을 더 크게 느낀다. 보상이 늦으면 행동이 중단된다.

**ReadTree 맥락**: 기록 작성의 보상이 즉각적인가? 포인트/통계/페르소나 진화는 언제 체감되는가?

### 1.5 프레이밍과 손실회피 (Framing & Loss Aversion)

**원리**: 같은 사실도 표현에 따라 판단이 달라진다. 이득보다 손실 회피가 2배 강하다.

**ReadTree 맥락**: "기록하면 포인트 획득" vs "기록 안 하면 스트릭 끊김" — 어느 쪽이 더 강한 동기부여인가?

## 2. 기능별 진단 및 개선안

### 2.1 독서 기록 (Notes) — 핵심 루프

> **적용 원칙**: 최소 노력 + 현재 편향 + 인지 부하

#### 현재 상태 분석

**QuickNote 플로우** (`components/notes/quick-note.tsx`):
1. 모드 선택 (인용/메모) → **판단 필요**
2. 책 선택 (최근 읽은 책 자동 선택됨) → OK
3. 내용 입력
4. 선택 필드(페이지, 태그, 공개 여부) → **판단 과다**
5. 저장

**NoteFormNew** (`components/notes/note-form-new.tsx`):
- `showOptionalFields` 토글로 필드를 숨기고 있으나, 여전히 제목/인용구절/메모/타입/페이지/태그/공개 여부 등 7+개 필드
- 보상: 포인트 적립 + `PRAISE_MESSAGES` 텍스트 피드백 → **지연 보상, 즉각성 부족**

#### 마찰 포인트

| # | 마찰 | 원칙 위반 | 심각도 |
|---|------|----------|--------|
| 1 | 모드(인용/메모) 선택이 첫 단계 | 인지 부하 | 높음 |
| 2 | 선택 필드가 보이면 "다 채워야 할 것 같은" 압박 | 최소 노력 | 중간 |
| 3 | 저장 후 보상이 텍스트 메시지뿐 | 현재 편향 | 높음 |
| 4 | 기록 직후 다음 행동 가이드 없음 | 최소 노력 | 중간 |

#### 개선안

1. **"한 줄 메모" 울트라 라이트 모드**: 텍스트 하나만 입력하면 저장. 타입은 자동으로 "메모"
2. **기본 타입을 "메모"로 고정**: 인용은 탭 전환으로 접근 (대부분의 사용자는 메모를 더 자주 씀)
3. **저장 직후 인라인 스트릭 표시**: "오늘 3번째 기록! 🔥 5일 연속" — 모달이 아닌 토스트/인라인
4. **"나중에 정리하기" 패턴**: 일단 빠르게 저장, 나중에 태그/페이지/분류 추가 가능

### 2.2 서재 관리 (Books/Bookshelves)

> **적용 원칙**: 기본값 효과 + 최소 노력

#### 현재 상태 분석

- 책 추가: `/books/search` 페이지로 이동 필요 → **페이지 전환 마찰**
- `book-status-selector.tsx`: 상태(읽는 중/읽을 예정/완독) 선택을 사용자에게 위임
- `book-info-editor.tsx`, `total-pages-editor.tsx`: 편집 기능 세분화

#### 마찰 포인트

| # | 마찰 | 원칙 위반 | 심각도 |
|---|------|----------|--------|
| 1 | 책 추가 시 별도 페이지 전환 | 최소 노력 | 높음 |
| 2 | 상태/서가/페이지수 모두 수동 선택 | 기본값 | 중간 |
| 3 | 검색 결과에서 책 선택 후 추가 정보 입력 요구 | 인지 부하 | 중간 |

#### 개선안

1. **스마트 기본값**: 상태="읽는 중", 서가="기본 서가", 총 페이지수=API 자동 채움
2. **대시보드 인라인 검색**: 페이지 전환 없이 모달/시트로 책 추가
3. **"어제 어디까지 읽었나요?"**: 진행률 업데이트를 푸시형 입력으로 전환 (대시보드에서 직접)

### 2.3 온보딩 (Onboarding)

> **적용 원칙**: 기본값 효과 + 손실회피 + 현재 편향

#### 현재 상태 분석

- `onboarding-wizard.tsx`: 3단계(약관 → 목표 → 튜토리얼), 실제로는 약관 후 바로 대시보드로 이동
- `onboarding-checklist.tsx`: 3개 항목(첫 책 추가 35P, 첫 노트 50P, 프로필 완성 50P)
- `grantWelcomeBonus`: 가입 시 200P 자동 지급 → **시각적 강조 부족**

#### 마찰 포인트

| # | 마찰 | 원칙 위반 | 심각도 |
|---|------|----------|--------|
| 1 | 약관 동의 후 바로 빈 대시보드 | 현재 편향 | 높음 |
| 2 | 웰컴 보너스 200P가 눈에 안 띔 | 손실회피 | 중간 |
| 3 | 체크리스트가 0/3에서 시작 (진전감 없음) | 기본값 | 중간 |
| 4 | 핵심 행동(첫 책 추가)까지 가이드 약함 | 최소 노력 | 높음 |

#### 개선안

1. **Endowed Progress 강화**: 체크리스트를 5개 항목(가입 완료 ✅, 약관 동의 ✅, 첫 책 추가, 첫 노트, 프로필)으로 확장 → 2/5 완료 상태로 시작
2. **웰컴 보너스 시각적 폭발**: "200P 획득!" 애니메이션 → "이 포인트로 AI 요약 2회 사용 가능"
3. **핵심 행동 바로 유도**: 온보딩 직후 "지금 읽고 있는 책이 있나요?" → 검색 → 1탭 추가
4. **3일차 넛지**: "목표를 설정한 사용자는 독서량이 2배" 메시지 (지연된 가치 경험 후 요청)

### 2.4 게이미피케이션 (Points/Streak/Persona)

> **적용 원칙**: 현재 편향 + 손실회피

#### 현재 상태 분석

- `earnPoints`: 15가지 이상 적립 액션 타입 → **적립은 풍부**
- `POINT_SPEND_COSTS`: AI 요약, 챗봇, 리포트 3종만 → **소비처 부족**
- `streakStatus: "at_risk"` 존재하지만 `weekly-progress-bar.tsx`에서만 사용 → **손실 프레이밍 미약**
- `getDailyMissions`: 2-3개 단순 미션 → **성취감 균형 문제**

#### 마찰 포인트

| # | 마찰 | 원칙 위반 | 심각도 |
|---|------|----------|--------|
| 1 | 포인트 적립은 많은데 쓸 곳이 없음 | 현재 편향 | 높음 |
| 2 | 스트릭 끊겨도 "잃는 느낌"이 없음 | 손실회피 | 높음 |
| 3 | 페르소나 진화 간격이 커서 변화 체감 불가 | 현재 편향 | 중간 |
| 4 | 일일 미션이 너무 쉬워 성취감 부족 | 인지 부하 | 낮음 |

#### 개선안

1. **스트릭 끊김 경고 프레이밍**: "7일 연속 기록이 오늘 끊깁니다" → 대시보드 상단 배너
2. **"잃을 수 있는 것" 명시**: "5일 연속 기록 배지가 사라집니다" vs "내일 6일 달성!"
3. **포인트 소비처 확장**: 커스텀 테마, 독서 리포트 디자인, 프로필 꾸미기 등 "지금 쓸 수 있는 것"
4. **페르소나 마이크로 진화**: 레벨업 사이에도 경험치 바, 작은 외형 변화 표시
5. **일일 미션 난이도 적응**: 사용 패턴에 따라 미션 난이도 자동 조정

### 2.5 AI 기능 (Chat/OCR/Report)

> **적용 원칙**: 최소 노력 + 인지 부하 + 현재 편향

#### 현재 상태 분석

- AI 챗봇: 별도 `/chat` 페이지, 포인트 소비 필요
- AI 요약/리포트: 포인트 소비, 데이터 축적 필요
- OCR: 사진 → 텍스트 변환, 가장 즉각적 유틸리티

#### "말은 하지만 안 쓸" 위험 분석

AI 기능은 사용자 인터뷰에서 "있으면 좋겠다"고 높은 응답률을 보이지만, 실제 사용률은 낮을 가능성이 높다:
- **진입 마찰**: 별도 화면 이동 필요
- **비용 인지**: 포인트 소비 → "아까워서" 안 씀
- **가치 불확실**: "눌러봐야 뭐가 나올지 모름"

#### 개선안

1. **OCR 일일 3회 무료**: 가장 즉각적 가치를 제공하는 기능을 무료 티어에 포함
2. **AI 챗봇 → "독서 복습 퀴즈"**: 수동적 기능을 능동적 습관으로 리프레이밍
3. **월간 리포트 자동 생성**: 사용자가 요청하지 않아도 매월 1일 자동 생성 (기본값 효과)
4. **AI 인사이트 스니펫**: 대시보드에 "이번 주 읽은 책에서 가장 많이 메모한 키워드" 같은 마이크로 인사이트 자동 노출

### 2.6 독서 모임 (Groups)

> **적용 원칙**: 인지 부하 + 최소 노력

#### 현재 상태 분석

- 그룹 생성 → 설정 → 초대 링크 공유 → 멤버 합류 → 공유 노트 작성: **5단계 이상**
- 네트워크 효과 필요: 다른 멤버가 없으면 빈 화면
- `group-note-feed.tsx`, `share-note-dialog.tsx` 구현 완료

#### "말은 하지만 안 쓸" 위험 분석

독서 모임은 **위험도 최고** 기능:
- "같이 읽으면 좋겠다"는 열망 → 현실: 혼자 읽는 게 편함
- 초대할 사람이 없으면 기능 자체가 무의미
- 모임 유지 비용(정기 참여, 기록 공유) > 개인 이득

#### 개선안

1. **"공개 독서 기록" 기본 활성화**: 모임 없이도 같은 책을 읽는 사람의 기록 열람 가능
2. **"이 책을 읽고 있는 N명"**: 책 상세 페이지에 사회적 증거 표시
3. **모임 → "같이 읽기"로 리브랜딩**: 무거운 "모임 생성"이 아닌, 가벼운 "같이 읽기" 버튼
4. **자동 매칭 제안**: "같은 책을 읽는 3명이 있습니다. 함께 읽을까요?" 넛지

### 2.7 통계/프로필 (Stats/Profile)

> **적용 원칙**: 현재 편향 + 프레이밍

#### 현재 상태 분석

- 통계 페이지: 데이터 축적 필요 → 신규 사용자에게 빈 화면
- `sample.ts`: 게스트에게 샘플 데이터 표시 → **좋은 접근**
- 연간 리포트: `yearly-report.tsx` → 연말에만 의미

#### 마찰 포인트

| # | 마찰 | 원칙 위반 | 심각도 |
|---|------|----------|--------|
| 1 | 통계가 의미 있으려면 2주+ 데이터 필요 | 현재 편향 | 높음 |
| 2 | "지난주 대비" 비교가 없어 변화 체감 불가 | 프레이밍 | 중간 |
| 3 | 연간 리포트는 너무 먼 미래 보상 | 현재 편향 | 중간 |

#### 개선안

1. **마이크로 통계 대시보드 상시 노출**: "이번 주 읽은 페이지: 47p", "오늘 기록: 2건"
2. **비교 프레이밍**: "지난주 대비 +20% 더 읽었어요" (손실회피 활용)
3. **주간 리포트 자동 발송**: 매주 월요일 "지난 주 독서 요약" 푸시/이메일
4. **신규 사용자 목표 대비**: "목표 대비 35% 달성 중" — 첫 날부터 의미 있는 수치 제공

### 2.8 구독/결제 (Subscription)

> **적용 원칙**: 손실회피 + 프레이밍

#### 현재 상태 분석

- 3단계 구독 체계: Free → Pro → Premium
- `pricing-banner.tsx`: 대시보드 하단 위치
- "유료 기능을 사용하세요" 이득 프레이밍

#### 마찰 포인트

| # | 마찰 | 원칙 위반 | 심각도 |
|---|------|----------|--------|
| 1 | 프리미엄 기능 가치를 경험 전에 결제 요청 | 기본값 | 높음 |
| 2 | "사세요" 이득 프레이밍만 사용 | 손실회피 | 중간 |
| 3 | 구독 배너가 대시보드 하단이라 눈에 안 띔 | 인지 부하 | 낮음 |

#### 개선안

1. **"3회 무료 체험" Endowment Effect**: 프리미엄 기능을 먼저 써보게 하고, "체험 종료" 후 구독 유도
2. **손실 프레이밍**: "프리미엄 사용자의 평균 독서량은 2.3배" → "무료 플랜에서는 이 기능을 잃게 됩니다"
3. **카운트다운**: "7일 무료 체험 종료까지 N일" — 타이머 시각화
4. **사회적 증거**: "이번 달 N명이 Pro로 업그레이드했습니다"

## 3. "말은 하지만 안 쓸 기능" 위험도 분석

아티클의 핵심 통찰: **사용자의 말(발화)은 단서(Clue)이고, 행동이 증거(Evidence)**다.

| 기능 | 사용자 발화 예상 | 실제 행동 예측 | 위험도 | 근거 |
|------|-----------------|---------------|--------|------|
| **AI 챗봇** | "AI로 책 토론하면 좋겠다" | 1-2회 시도 후 방치 | **높음** | 포인트 소비 + 별도 진입 + 즉각 가치 불명확 |
| **독서 모임** | "같이 읽으면 동기부여 될 것" | 그룹 생성만 하고 활동 없음 | **높음** | 네트워크 효과 필요 + 진입 마찰 + 유지 비용 |
| **AI 리포트** | "독서 분석 받아보고 싶다" | 한 번 생성 후 재사용 낮음 | **중간** | 데이터 축적 필요 + 포인트 소비 + 반복 가치 불확실 |
| **페르소나** | "재미있을 것 같다" | 초기 흥미 후 변화 없으면 무관심 | **중간** | 진화 간격이 크면 관심 저하 |
| **자유 노트** | "책 외 메모도 하고 싶다" | 실제 활발히 사용 | **낮음** | 마찰 낮고 즉각적 가치 |
| **OCR** | "사진으로 기록하면 편할 것" | 실제 활발히 사용 | **낮음** | 즉각적 유틸리티 명확 |
| **서재 관리** | "책 정리하고 싶다" | 핵심 기능으로 지속 사용 | **낮음** | 기본 니즈, 진입 마찰 개선 시 활성화 |

### 위험 완화 전략

**높은 위험 기능**에 대한 접근:
- 기능을 삭제하는 것이 아니라, **진입 경로와 가치 제안을 재설계**
- AI 챗봇 → "독서 복습 퀴즈"로 리프레이밍 (수동 → 능동)
- 독서 모임 → "공개 기록 + 같이 읽기"로 마찰 최소화

## 4. 계측(Instrumentation) 설계

> "행동 데이터는 자연 발생하지 않는다. 정의해야 한다." — 아티클

### 핵심 이벤트 정의

#### 독서 기록

| 이벤트 | 속성 | 측정 대상 |
|--------|------|----------|
| `note_form_opened` | `source` (dashboard/book_detail/fab) | 진입 경로 |
| `note_type_selected` | `type` (memo/quote/free) | 선택 패턴 |
| `note_created` | `type`, `duration_ms`, `field_count`, `has_image` | 완료율/마찰 |
| `note_abandoned` | `step`, `duration_ms` | 이탈 지점 |

#### 서재 관리

| 이벤트 | 속성 | 측정 대상 |
|--------|------|----------|
| `book_search_initiated` | `source` (dashboard/search_page) | 진입 경로 |
| `book_added` | `source`, `time_to_add_ms`, `fields_modified` | 추가 마찰 |
| `book_status_changed` | `from_status`, `to_status` | 진행 패턴 |

#### 게이미피케이션

| 이벤트 | 속성 | 측정 대상 |
|--------|------|----------|
| `streak_warning_shown` | `streak_days`, `context` | 경고 노출 |
| `streak_warning_acted` | `action` (created_note/dismissed) | 행동 전환 |
| `points_spent` | `feature`, `amount` | 소비 패턴 |
| `daily_mission_completed` | `mission_type`, `time_to_complete_ms` | 미션 효과 |

#### AI 기능

| 이벤트 | 속성 | 측정 대상 |
|--------|------|----------|
| `ai_feature_used` | `type` (chat/summary/report/ocr), `points_spent` | 사용 패턴 |
| `ai_feature_result_action` | `action` (saved/shared/dismissed) | 결과 가치 |

### 교차검증 지표 (3-Metric Framework)

아티클의 핵심: 단일 지표가 아닌 **채택-습관화-임팩트**로 분석

| 지표 | 정의 | 해석 |
|------|------|------|
| **채택률 (Adoption)** | 7일 내 기능 첫 사용 비율 | 진입 장벽 |
| **습관화 (Retention)** | D7/D14/D30 반복 사용률 | 지속 가치 |
| **임팩트 (Impact)** | 핵심 지표(주간 기록 수, 스트릭 길이) 변화 | 비즈니스 가치 |

**해석 매트릭스**:
- 채택 낮음 + 유지 높음 → **UX가 진입을 어렵게 만듦** (온보딩/발견성 문제)
- 채택 높음 + 유지 낮음 → **가치 전달 실패** (콘텐츠/품질 문제)
- 채택 높음 + 유지 높음 + 임팩트 낮음 → **핵심 루프와 연결 부족**

## 6. 우선순위 매트릭스

### 영향력 × 구현 난이도

```
높은 영향력
    │
    │  ★ 한줄메모 모드     ★ 스트릭 손실 프레이밍
    │  ★ OCR 무료 티어     ★ 월간 자동 리포트
    │
    │  ★ 노트 기본값       ★ 소셜 증거 ("N명")
    │  ★ 온보딩 개선       ★ 복습 퀴즈 리프레이밍
    │  ★ 스트릭 경고       ★ 프리미엄 무료 체험
    │
낮은 영향력────────────────────────────────
    낮은 난이도                     높은 난이도
```

### 즉시 실행 추천 (Quick Wins)

왼쪽 상단 사분면 — **높은 영향력 + 낮은 난이도**:

1. 노트 폼 기본 타입 "메모" 설정
2. 스트릭 끊김 경고 프레이밍 변경
3. 온보딩 체크리스트 Endowed Progress
4. 책 추가 기본 상태 "읽는 중"
5. 웰컴 보너스 시각 강조

## 참고: 아티클 핵심 인용

> "말과 행동이 다르다는 사실 자체가 힌트고, 그 힌트를 증거로 바꾸는 과정이 바로 UX의 일"

> "사용자는 의지로 움직이는 존재가 아니라 마찰과 기본값과 맥락에 반응하는 존재"

> "유저가 틀렸다고 선언하는 것이 아니라, 말과 행동의 간극을 전제로 설계를 시작하는 것"

### 사이클

**단서(발화) → 가설 → 계측 → 관찰 → 교차검증 → 해석 → 실험 → 인과 확인**

이 사이클이 쌓이면, 유저의 말이 "위험한 소음"에서 "제품을 정교하게 만드는 힌트"로 변환된다.
