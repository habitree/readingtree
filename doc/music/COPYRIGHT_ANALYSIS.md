## 1. 개요

### 1.1 기능 목적

ReadingTree 앱에서 독서 중 클래식 음악을 배경음악으로 재생하는 기능을 추가한다. 클래식 음악은 집중력 향상에 효과적이며, 독서 경험을 풍부하게 만드는 핵심 부가 기능이다.

### 1.2 분석 범위

| 항목 | 범위 |
|------|------|
| 음악 장르 | 서양 클래식 음악 (바로크~낭만주의) |
| **확정 전략** | **자체 오디오 호스팅(앱 재생) + YouTube 채널(홍보/유입)** |
| 적용 법령 | 한국 저작권법, YouTube TOS (채널 운영) |
| 서비스 성격 | 상업적 서비스 (유료 포인트 충전 존재) |

### 1.3 확정 아키텍처 개요

```

│                     동일한 PD 음원 소스                       │
```

## 2. 클래식 음악 저작권 3단 구조

클래식 음악의 저작권은 **3개의 독립된 권리**로 구성된다. 작곡이 퍼블릭 도메인이라 해도 **연주 녹음**에는 별도 권리가 존재한다.

```
┌─────────────────────────────────────────────┐
│          클래식 음악 저작권 구조              │
├─────────────────────────────────────────────┤
│                                             │
│  ① 작곡 저작권 (저작재산권)                  │
│     → 작곡가 사망 후 70년                    │
│     → 바흐, 모차르트 등 대부분 PD ✅          │
│                                             │
│  ② 실연자 저작인접권                         │
│     → 연주(실연)한 때로부터 70년              │
│     → 현대 오케스트라 녹음 대부분 보호 중 ⚠️  │
│                                             │
│  ③ 음반제작자 권리                           │
│     → 음반 발행일로부터 70년                  │
│     → 메이저 레이블 녹음 대부분 보호 중 ⚠️    │
│                                             │
└─────────────────────────────────────────────┘
```

### 2.2 실연자 저작인접권 (제64조) — 실연 후 70년

**근거**: 저작권법 제64조 (실연자의 보호기간)

> 실연자의 인접저작권은 그 실연을 한 때부터 70년간 존속한다. (2013.8.1 개정, 이전 50년)

#### 핵심 포인트

- **2026년 기준**: 1956년 이전의 실연만 보호기간 소멸
- 현대 오케스트라(빈 필하모닉, 베를린 필하모닉 등)의 녹음은 **거의 모두 보호 중**
- 지휘자, 독주자, 오케스트라 단원 **모두** 실연자에 해당
- 작곡이 퍼블릭 도메인이어도 **연주 녹음은 별도 허가 필요**

#### 실무적 의미

```
바흐 "골드베르크 변주곡" (1741년 작곡) → 작곡 저작권: PD ✅
  └─ 글렌 굴드 1981년 녹음 → 실연자 권리: 2051년까지 보호 ❌
  └─ 무명 연주자 1950년 녹음 → 실연자 권리: 2020년 소멸 ✅
  └─ Musopen 2012년 녹음 (CC 라이선스) → 라이선스 조건에 따라 사용 가능 ✅
```

### 2.3 음반제작자 권리 (제66조) — 발행 후 70년

**근거**: 저작권법 제66조 (음반제작자의 보호기간)

> 음반제작자의 인접저작권은 그 음반을 발행한 때부터 70년간 존속한다.

#### 핵심 포인트

- **2026년 기준**: 1956년 이전 발행 음반만 보호기간 소멸
- EMI, Deutsche Grammophon, Decca 등 **메이저 레이블의 녹음은 대부분 보호 중**
- 음반제작자 = 녹음의 기획·제작·비용 부담 주체 (보통 레코드 레이블)
- 실연자 권리와 **별도로** 존재 → 두 가지 모두 확인 필요

### 2.4 보호기간 요약표

| 권리 유형 | 기산점 | 보호기간 | 2026년 기준 PD 조건 | 근거 조항 |
|-----------|--------|---------|-------------------|----------|
| 작곡 저작권 | 저작자 사망 | 70년 | 1956년 이전 사망 | 제39조 |
| 실연자 권리 | 실연한 때 | 70년 | 1956년 이전 실연 | 제64조 |
| 음반제작자 권리 | 음반 발행 | 70년 | 1956년 이전 발행 | 제66조 |

> **핵심 결론**: 클래식 음악을 자유롭게 사용하려면 ① 작곡 PD + ② 실연 PD + ③ 음반 PD **세 가지 모두** 충족하거나, CC/로열티프리 라이선스가 부여된 녹음을 사용해야 한다.

## 3. YouTube 임베딩 법적 분석

### 3.1 YouTube TOS 허용 범위

YouTube는 공식적으로 임베딩을 지원하며, 다음 조건에서 **상업적 웹사이트/앱에서의 임베딩도 허용**한다:

- 영상 업로더가 임베딩을 비활성화하지 않았을 것
- YouTube IFrame Player API 또는 embed URL을 통한 표준 방식 사용
- YouTube 로고/브랜딩 가시 유지
- YouTube 이용약관 및 API 서비스 약관 준수

**참고**: YouTube 영상 자체의 저작권 문제는 **업로더의 책임**이며, 임베딩하는 서비스는 저작권 침해의 직접 당사자가 아님 (단, 명백히 불법 콘텐츠를 알면서 임베딩하는 경우 제외).

### 3.2 Required Minimum Functionality 핵심 규정

YouTube API를 사용하는 모든 API Client는 다음을 준수해야 한다:

| 규정 | 내용 | 위반 시 |
|------|------|--------|
| **최소 플레이어 크기** | 200 x 200 픽셀 이상 | API 접근 차단 |
| **백그라운드 재생 금지** | API 서비스 창이 닫히거나 최소화될 때 재생 중단 | API 접근 차단 |
| **오버레이 금지** | 플레이어 위에 HTML 요소 배치 불가 | API 접근 차단 |
| **자동재생 조건** | 플레이어가 화면에 보이고 50% 이상 노출 시에만 | API 접근 차단 |
| **플레이어 수정 금지** | API 문서에 명시되지 않은 플레이어 변경 불가 | API 접근 차단 |

### 3.3 "오디오 전용" 사용의 위험성 — 🔴 CRITICAL

**YouTube 플레이어를 숨기고 오디오만 재생하는 것은 명백한 TOS 위반이다.**

구체적 금지 행위:
- `display: none`으로 플레이어 숨기기
- `opacity: 0`으로 투명하게 만들기
- 화면 밖으로 플레이어 이동 (`position: absolute; left: -9999px`)
- 1x1 픽셀 크기로 축소
- 다른 요소로 플레이어 완전히 덮기
- 앱이 백그라운드에 있을 때 재생 유지

**이유**: 백그라운드 재생 / 오디오 전용 재생은 **YouTube Premium의 핵심 유료 기능**이다. 이를 무료로 우회하는 것은 YouTube의 수익 모델을 직접 침해하므로 가장 엄격하게 단속되는 영역이다.

**위반 결과**:
- API 키 즉시 차단
- Google Cloud 계정 정지 가능
- YouTube API 서비스 약관 위반으로 법적 조치 가능

### 3.4 상업적 앱에서의 합법적 임베딩 방법

YouTube 임베딩을 합법적으로 사용하는 유일한 방법:

```
✅ 합법적 사용
┌──────────────────────────────────────┐
│  독서 화면                            │
│  ┌──────────────────────────────┐    │
│  │                              │    │
│  │     책 내용 / 독서 영역        │    │
│  │                              │    │
│  └──────────────────────────────┘    │
│                                      │
│  ┌──────────────────────────────┐    │
│  │  ▶ YouTube 미니 플레이어       │    │
│  │  (200x200px 이상, 항상 보임)   │    │
│  └──────────────────────────────┘    │
└──────────────────────────────────────┘

❌ 불법적 사용
- 플레이어 숨기고 오디오만 재생
- 앱 최소화 후 백그라운드 재생
- 1x1 픽셀 플레이어
```

## 4. 한국 저작권법 적용

### 4.1 제29조 (비영리 공연) 적용 불가 분석

저작권법 제29조 (영리를 목적으로 하지 아니하는 공연·방송):

> ① 영리를 목적으로 하지 아니하고 청중이나 관중 또는 제3자로부터 어떤 명목으로든지 반대급부를 받지 아니하는 경우에는 공표된 저작물을 공연 또는 방송할 수 있다. 다만, 실연자에게 통상의 보수를 지급하는 경우에는 그러하지 아니하다.

#### ReadingTree에 적용 불가 이유

| 요건 | 충족 여부 | 근거 |
|------|----------|------|
| 영리 목적 없을 것 | ❌ 불충족 | ReadingTree는 유료 포인트 충전이 있는 상업적 서비스 |
| 청중으로부터 대가 없을 것 | ❌ 불충족 | 앱 사용자가 포인트를 구매하며, 음악이 서비스 매력도를 높이는 요소 |
| 실연자에게 보수 없을 것 | - | 위 두 요건 불충족으로 판단 불요 |

> **결론**: "음악 재생 자체는 무료"라는 주장은 앱 전체의 영리 목적과 분리할 수 없다. 제29조 예외 적용 **불가**.

### 4.2 음악저작권 집중관리단체

| 단체 | 관리 대상 | ReadingTree 관련성 |
|------|----------|-------------------|
| **KOMCA** (한국음악저작권협회) | 작곡/작사 저작권 | PD 클래식은 해당 없음. 20세기 보호 중 작곡가 사용 시 이용허락 필요 |
| **KOSCAP** (함께하는음악저작인협회) | 작곡/작사 저작권 (선택위탁) | 동상 |
| **FKMP** (한국음악실연자연합회) | 실연자 보상청구권 | 디지털 음원 전송 시 보상금 청구 가능 |
| **RIAK** (한국음반산업협회) | 음반제작자 권리 | 디지털 음원 전송 시 이용허락 필요 |

### 4.3 전송권과 스트리밍

저작권법 제18조 (전송권):

> 저작자는 그의 저작물을 전송할 권리를 가진다.

- YouTube 임베딩 = YouTube가 전송 → ReadingTree는 전송 주체가 아님 (링크/임베딩은 전송이 아닌 것이 통설)
- 자체 호스팅 = ReadingTree가 전송 주체 → 전송권 확보 필요 (PD 녹음 또는 CC 라이선스 필수)

## 7. 확정 전략: 자체 오디오 재생 + YouTube 채널 홍보 연결

### 7.0 전략 개요

**동일한 PD 음원**을 두 채널에서 독립적으로 활용하여 상호 시너지를 만든다.

| 채널 | 역할 | 기술 |
|------|------|------|
| **앱 내 재생** | 핵심 사용자 경험 (독서 배경음악) | 자체 호스팅 + HTML5 Audio API |
| **YouTube 채널** | 마케팅/유입 + 브랜딩 + SEO | 정적 이미지 + PD 음원 영상 |

**핵심 원칙**: YouTube에서 음원을 추출하지 않는다. 앱과 YouTube 모두 **원본 PD 소스(Musopen 등)에서 독립적으로** 음원을 확보한다.

### 7.1 앱 내 자체 오디오 재생 (메인 기능)

#### 기술 스택

| 구성 요소 | 기술 | 비고 |
|-----------|------|------|
| 오디오 호스팅 | Supabase Storage 또는 CDN | MP3 128kbps (모바일) / 320kbps (데스크톱) |
| 플레이어 | HTML5 Audio API + Web Audio API | 커스텀 UI 완전 제어 |
| 상태 관리 | zustand (`use-music-player.ts`) | 재생 상태, 볼륨, 플레이리스트 |
| UI | 48px 슬림 미니 플레이어 | 모바일 네비(56px) 위 배치 |
| 잠금 화면 | Media Session API | 곡 정보 + 재생 컨트롤 표시 |
| 오프라인 | Service Worker 캐시 | 자주 듣는 곡 오프라인 재생 |

#### 주요 장점

- ✅ **백그라운드 재생**: 화면 잠금/앱 전환 후에도 계속 재생 (Android PWA)
- ✅ **슬림 UI**: 48px 바만으로 완전한 배경음악 (YouTube 200x200px 제약 없음)
- ✅ **오프라인 재생**: Service Worker 캐시로 네트워크 없이도 재생
- ✅ **데이터 절약**: 오디오만 스트리밍 (비디오 없음)
- ✅ **광고 없음**: YouTube 광고 노출 없이 깔끔한 경험
- ✅ **완전한 UX 제어**: 플레이리스트 연속 재생, 셔플, 반복 자유 구현

#### YouTube 연결 포인트 (앱 → YouTube)

앱 내 음악 플레이어에서 YouTube 채널로 자연스럽게 연결:

```
┌───────────────────────────────────────┐
│ 🎵 미니 플레이어                        │
│ ▶  바흐 — 무반주 첼로 모음곡 1번  ⏸ ⏭  │
│ ──●──────────── 1:24 / 4:02          │
│                                       │
│ [YouTube에서 보기 ↗]  [전체 재생목록 ↗] │ ← 채널 유입 링크
└───────────────────────────────────────┘
```

- 각 트랙에 `youtube_video_id` 저장 → "YouTube에서 보기" 링크 제공
- 플레이리스트 화면에서 "YouTube에서 전체 듣기" 버튼
- 앱 설정에서 ReadingTree YouTube 채널 구독 유도

### 7.2 YouTube 채널 운영 (홍보/마케팅)

#### 채널 목적

```
YouTube 채널의 역할:
  ① 앱 유입 채널 → 영상 설명란에 앱 다운로드/링크
  ② 브랜드 인지도 → "독서 + 클래식" 연상 이미지 구축
  ③ SEO/검색 → "독서 배경음악", "공부 클래식" 키워드 점유
  ④ 커뮤니티 → 댓글로 사용자 소통, 곡 요청 수집
```

#### 영상 제작 워크플로우

```
1. 음원 확보
   └─ Musopen에서 PD 녹음 다운로드
   └─ 라이선스 증빙 PDF/스크린샷 보관 (doc/music/licenses/)

2. 배경 이미지 제작
   └─ ReadingTree 브랜딩 일러스트 (1920x1080)
   └─ 카테고리별 4종: 집중/편안한 독서/깊은 사색/활력
   └─ 또는 Unsplash/Pexels 상업 무료 이미지

3. 영상 합성
   └─ FFmpeg:
      ffmpeg -loop 1 -i bg.jpg -i audio.mp3 \
        -c:v libx264 -tune stillimage \
        -c:a aac -b:a 192k \
        -shortest -pix_fmt yuv420p output.mp4

4. YouTube 업로드 + 메타데이터
   └─ 제목: "바흐 무반주 첼로 모음곡 1번 | 독서 배경음악 🎵📚"
   └─ 설명:
      - 작곡가, 곡명, 연주자 크레딧
      - 라이선스 출처 (Musopen PD)
      - "ReadingTree 앱에서 독서하며 들어보세요 → [앱 링크]"
      - 타임스탬프 (장시간 컴필레이션의 경우)
   └─ 태그: classical music, study bgm, reading music, 독서 음악
   └─ 엔드스크린: ReadingTree 앱 소개 카드

5. 앱 DB 연동
   └─ music_tracks 테이블에 youtube_video_id 필드 업데이트
   └─ 앱 내 "YouTube에서 보기" 링크 활성화
```

#### YouTube → 앱 유입 전략

| 터치포인트 | 내용 |
|-----------|------|
| 영상 설명란 | "ReadingTree에서 독서하며 들어보세요 → [링크]" + UTM 파라미터 |
| 엔드스크린 (마지막 20초) | 앱 소개 카드 + 구독 버튼 |
| 고정 댓글 | "이 곡을 독서 배경음악으로 듣고 싶다면 ReadingTree 앱을 확인해보세요" |
| 채널 소개 | ReadingTree 앱 설명 + 링크 |
| 커뮤니티 탭 | 독서 팁 + 음악 추천 + 앱 업데이트 소식 |

#### 앱 → YouTube 유입 전략

| 터치포인트 | 내용 |
|-----------|------|
| 미니 플레이어 | "YouTube에서 보기 ↗" 링크 (트랙별) |
| 플레이리스트 화면 | "YouTube에서 전체 듣기 ↗" 버튼 |
| 음악 설정 페이지 | ReadingTree YouTube 채널 구독 안내 |
| 독서 완료 카드 | "이 곡과 함께 독서 완료! YouTube에서 공유하기" |
| 공유 기능 | "OO곡 들으며 OO책 읽는 중" YouTube 링크 포함 공유 |

#### Content ID 오인 클레임 대응

PD 녹음이라도 YouTube Content ID가 유사한 상업 녹음과 매칭하여 자동 클레임을 발행할 수 있다. 이는 오인(false positive)이다.

**대응 절차**: 클레임 수신 → 보관된 PD/CC 증빙 첨부 → 이의 제기 → 30일 내 미반박 시 자동 해제

**예방**: Musopen 자체 녹음 우선 사용 (Content ID 등록 가능성 낮음), 영상 설명란에 라이선스 출처 명시

### 7.3 구현 로드맵

#### Phase 1 — 앱 내 자체 오디오 + YouTube 채널 개설 (3주)

**앱 개발 (2주)**:
- Musopen PD 녹음 10~20곡 다운로드 + 라이선스 검증
- Supabase Storage 업로드 + CDN 설정
- DB 마이그레이션 (music_playlists, music_tracks, user_music_preferences)
- HTML5 Audio 기반 미니 플레이어 컴포넌트
- zustand 상태 관리 스토어
- 플레이리스트 선택 UI (카테고리별 4종)
- Media Session API 연동 (잠금 화면 컨트롤)

**YouTube 채널 (1주, 앱 개발과 병행)**:
- ReadingTree Music 채널 개설
- 브랜딩 이미지 4종 제작 (카테고리별)
- FFmpeg로 영상 10편 제작 + 업로드
- 영상 설명란에 앱 링크 + UTM 파라미터 설정
- 앱 DB에 youtube_video_id 연동

#### Phase 2 — 고도화 (4주)

- 플레이리스트 확장 (카테고리당 20곡+)
- Service Worker 오프라인 캐시
- 셔플/반복 모드
- YouTube 장시간 컴필레이션 영상 (1~3시간)
- 앱 내 "YouTube에서 보기" 딥링크
- 독서 완료 카드에 음악 정보 공유 기능
- 저대역폭 자동 전환 (128kbps)

#### Phase 3 — 확장 (장기)

- AI 기반 분위기 추천 (독서 장르별 자동 매칭)
- 독서 타이머 연동 (타이머 종료 시 페이드 아웃)
- 사용자 커뮤니티 플레이리스트 공유
- 자체 연주 커미셔닝 (대학 오케스트라 등과 협업)
- AI 생성 클래식 풍 음악 (Suno, Udio 등 검토)
- YouTube 커뮤니티 탭 활용 독서 모임 운영

- 재생/정지/이전/다음곡 + 프로그레스 바 시킹
- Media Session API (잠금 화면 컨트롤)
- 곡 종료 시 다음 곡 자동 재생 → **1시간 연속 재생**

## 8. 모바일 환경 분석 및 전략

### 8.1 모바일 핵심 문제점

ReadingTree는 PWA(standalone) 모드로 동작하며 모바일 사용자가 다수이다. YouTube 임베딩의 모바일 제약은 **심각한 UX 한계**를 만든다.

| 문제 | 심각도 | 설명 |
|------|--------|------|
| 백그라운드 재생 불가 | 🔴 CRITICAL | 화면 잠금/앱 전환/카톡 확인 시 YouTube 재생 즉시 중단 |
| 자동재생 완전 차단 | 🔴 HIGH | 모바일 브라우저/PWA에서 사용자 터치 없이 자동재생 불가 |
| 화면 공간 부족 | 🟡 MEDIUM | 375px 화면에서 200x200px 플레이어 = 화면 너비의 53% |
| 하단 네비 충돌 | 🟡 MEDIUM | 모바일 네비(56px) + 플레이어(64px+) = 하단 120px+ 점유 |
| iOS 특수 제한 | 🟡 MEDIUM | Safari PWA에서 Audio 백그라운드 재생도 불안정 (15초 후 중단 가능) |

### 8.2 모바일 YouTube 임베딩 전략 (Phase 1)

**접이식(Collapsible) 미니 플레이어**:

```
[접힌 상태 - 기본, 48px]
┌──────────────────────────────────┐
│ ▶  바흐 — 첼로 모음곡 1번  ⏸ ⏭ ▲ │
└──────────────────────────────────┘

[펼친 상태 - 사용자 탭 시, ~140px]
┌──────────────────────────────────┐
│ ┌──────────┐  바흐 — 첼로 모음곡  │
│ │  YouTube  │  Musopen Orchestra  │
│ │  160x90   │  ⏮  ⏸  ⏭           │
│ └──────────┘  ──●────── 1:24/4:02 │
└──────────────────────────────────┘
```

- 기본은 48px 슬림 바 (곡 정보 + 컨트롤만)
- ▲ 탭 시 YouTube 플레이어가 펼쳐짐 (160x90px, TOS 준수)
- **YouTube가 보이는 상태에서만 재생** → 접으면 재생 중단 불가피

### 8.3 모바일 자체 오디오 전략 (Phase 2 — 강력 권장)

자체 호스팅 오디오는 YouTube의 모바일 제약을 대부분 해결한다:

| 기능 | YouTube (Phase 1) | 자체 오디오 (Phase 2) |
|------|-------------------|---------------------|
| 백그라운드 재생 | ❌ 불가 | ✅ Android PWA 가능, iOS 제한적 |
| 플레이어 크기 | 200x200px 필수 | 48px 슬림 바 가능 |
| 다음 곡 자동재생 | ❌ 불가 | ✅ 가능 (최초 터치 이후) |
| 오프라인 재생 | ❌ 불가 | ✅ Service Worker 캐시 |
| 데이터 사용량 | 높음 (비디오) | 매우 낮음 (오디오만) |
| 잠금 화면 컨트롤 | ❌ 불가 | ✅ Media Session API |

**Media Session API** — 잠금 화면/알림 센터에 미디어 컨트롤 표시:

```javascript
if ('mediaSession' in navigator) {
  navigator.mediaSession.metadata = new MediaMetadata({
    title: '무반주 첼로 모음곡 1번',
    artist: 'J.S. 바흐 · Musopen Orchestra',
    album: '집중 모드',
    artwork: [{ src: '/images/music/focus.png', sizes: '256x256' }]
  });
  navigator.mediaSession.setActionHandler('play', () => { /* 재생 */ });
  navigator.mediaSession.setActionHandler('pause', () => { /* 정지 */ });
  navigator.mediaSession.setActionHandler('nexttrack', () => { /* 다음곡 */ });
}
```

### 8.4 iOS vs Android 차이점

| 기능 | Android Chrome/PWA | iOS Safari/PWA |
|------|-------------------|----------------|
| HTML5 Audio 백그라운드 | ✅ PWA에서 가능 | ⚠️ 15초 후 중단 가능 |
| Media Session API | ✅ 완전 지원 | ⚠️ 부분 지원 (iOS 15+) |
| Service Worker 캐시 | ✅ 무제한 | ⚠️ 50MB 제한 |
| Wake Lock API | ✅ 지원 | ❌ 미지원 |

**iOS 대응**: 화면 유지 모드 제공 (Wake Lock 대안으로 무음 비디오 루프 기법), 또는 "화면을 켜둔 채 독서하세요" 안내.

### 8.5 권장 모바일 전략

> **핵심 결론**: YouTube 임베딩(Phase 1)은 모바일에서 심각한 UX 제약이 있다. **데스크톱 검증용 MVP로만 활용**하고, 모바일 사용자에게는 **Phase 2(자체 오디오)를 우선 적용**하는 것을 강력히 권장한다.

| 환경 | Phase 1 | Phase 2 (권장) |
|------|---------|---------------|
| 데스크톱 | YouTube 미니 플레이어 | 자체 오디오 + 슬림 바 |
| 모바일 | YouTube 접이식 (제한적) 또는 "곧 출시" 안내 | 48px 슬림 바 + Media Session API |
| PWA standalone | YouTube 제한적 | 네이티브 앱 수준 경험 |
