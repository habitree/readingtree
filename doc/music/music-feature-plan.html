확정 전략: 자체 오디오 + YouTube 홍보 연결

동일한 퍼블릭 도메인 음원을 앱(자체 호스팅)과 YouTube 채널(홍보) 두 채널에서 독립적으로 활용하여 상호 시너지를 만드는 전략입니다.

법적 결론: PD 작곡 + PD 녹음(Musopen 등)을 사용하면 앱 내 재생과 YouTube 채널 업로드 모두 저작권 문제 없음. YouTube에서 오디오를 추출하지 않으므로 YouTube TOS 위반도 없음.

금지 사항 (반드시 피해야 할 것)

YouTube → 오디오 추출 금지

YouTube 영상에서 오디오를 다운로드/추출하여 앱에 사용하는 것은 YouTube TOS 명시 위반입니다. 반드시 원본 소스(Musopen 등)에서 독립적으로 확보해야 합니다.

YouTube API 스트리밍 금지

YouTube API를 통해 영상/오디오를 앱 내에서 직접 스트리밍하면서 UI를 숨기는 것은 API TOS 위반입니다.

보호 중 녹음 사용 금지

작곡이 PD여도 유명 오케스트라의 현대 녹음은 실연자/음반 권리가 살아있습니다. PD 3중 확인(작곡+실연+음반) 필수.

YouTube TOS 핵심 금지사항

백그라운드 재생 금지

API 서비스 창이 닫히거나 최소화될 때 비디오 재생을 유지하는 것은 금지됩니다. YouTube Premium의 핵심 유료 기능입니다.

오디오 전용 사용 금지

플레이어를 숨기고(display:none, opacity:0, 화면 밖 이동) 오디오만 재생하는 것은 명시적으로 금지됩니다.

최소 플레이어 크기

YouTube 플레이어는 최소 200x200 픽셀 이상이어야 합니다. 이보다 작은 플레이어는 TOS 위반입니다.

오버레이 금지

YouTube 플레이어 위에 HTML 요소를 덮어씌우는 것은 금지됩니다. 플레이어가 완전히 보여야 합니다.

합법적 사용: YouTube 플레이어를 화면에 200x200px 이상으로 표시하고, 사용자가 수동으로 재생하며, 플레이어가 보이는 상태에서 음악을 듣는 것은 완전히 합법입니다.

자체 오디오 + YouTube 연결 아키텍처

데이터 흐름: ━━━━━━━━━━ Musopen PD 녹음 (원본) ├─→ Supabase Storage / CDN → music_tracks.source_url (앱 재생용) └─→ FFmpeg + 배경이미지 → YouTube 업로드 → music_tracks.youtube_video_id 앱 컴포넌트: ━━━━━━━━━━ audio-player.tsx (HTML5 Audio) ← source_url로 재생 └─ "YouTube에서 보기 ↗" ← youtube_video_id로 링크 생성 https://youtube.com/watch?v={youtube_video_id} 미니 플레이어: ━━━━━━━━━━ ┌─────────────────────────────────────────┐ │ ▶ 바흐 — 무반주 첼로 모음곡 1번 ⏸ ⏭ │ ← 자체 오디오 재생 │ ──●────────── 1:24/4:02 │ │ [YouTube에서 보기 ↗] │ ← YouTube 채널 유입 └─────────────────────────────────────────┘

source_url은 앱 내 재생용 CDN URL, youtube_video_id는 "YouTube에서 보기" 링크용입니다. 두 필드는 독립적이며, YouTube 영상이 없는 트랙도 앱에서 정상 재생됩니다.

3단계 구현 로드맵

Phase 1 자체 오디오 + YouTube 채널 개설 (3주)
앱 개발 2주 + YouTube 채널 1주 (병행)
앱 개발:
  • Musopen PD 녹음 10~20곡 다운로드 + 라이선스 검증
  • Supabase Storage 업로드 + CDN 설정
  • DB 마이그레이션 (music_playlists, music_tracks, user_music_preferences)
  • HTML5 Audio 기반 미니 플레이어 (48px 슬림 바)
  • zustand 상태 관리 + Media Session API
  • 플레이리스트 선택 바텀시트 (4개 카테고리)
  • "YouTube에서 보기 ↗" 링크 연동
YouTube 채널:
  • ReadingTree Music 채널 개설 + 브랜딩
  • 배경 이미지 4종 제작 (카테고리별)
  • FFmpeg로 영상 10편 합성 + 업로드
  • 영상 설명란 앱 링크 + UTM 파라미터
Phase 2 고도화 (4주)
플레이리스트 확장 + 오프라인 + YouTube 컴필레이션
  • 플레이리스트 확장 (카테고리당 20곡+)
  • Service Worker 오프라인 캐시
  • 셔플/반복 모드
  • 저대역폭 자동 전환 (128kbps)
  • 독서 완료 카드에 음악+YouTube 공유 기능
  • YouTube 장시간 컴필레이션 영상 (1~3시간) 4편
  • YouTube 커뮤니티 탭 운영 시작
Phase 3 확장 (장기)
AI 추천 + 커뮤니티 + YouTube 성장
  • AI 기반 분위기 추천 (독서 장르별 자동 매칭)

YouTube 채널 역할: 홍보/마케팅/유입 채널

YouTube 채널은 앱의 배경음악 기능을 직접 제공하는 것이 아니라, ReadingTree 앱으로 사용자를 유입시키는 마케팅 채널로 운영합니다.

모바일 환경 핵심 문제점

ReadingTree는 PWA(standalone) 모드로 동작하며, 모바일 사용자가 다수입니다. YouTube 임베딩의 모바일 제약을 정확히 이해해야 합니다.

1. 백그라운드 재생 불가

화면 잠금, 앱 전환, 탭 전환 시 YouTube 재생이 즉시 중단됩니다. iOS/Android 모두 해당. 독서 중 카톡 확인만 해도 음악이 멈춥니다.

2. 자동재생 완전 차단

모바일 브라우저/PWA에서 사용자 탭(터치) 없이 영상 자동 재생이 불가능합니다. 페이지 진입 시 자동으로 음악이 시작되지 않습니다.

3. 화면 공간 부족

375px 화면에서 YouTube 200x200px 플레이어 = 화면 너비의 53%. 독서 공간이 크게 줄어들며 UX가 저하됩니다.

4. 하단 네비 + 플레이어 충돌

모바일 네비(56px) + 미니 플레이어(64px+) = 하단 120px 이상 점유. 독서 영역이 크게 축소됩니다.

시나리오: 출퇴근길 독서
