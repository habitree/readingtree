1. 현황 분석

현재 챗봇 구조 요약

현재 독서친구 챗봇은 lib/ai/prompts/chat-prompts.ts에 정의된 약 15줄의 시스템 프롬프트로 동작합니다. 기능적으로는 작동하지만, 심층 독서 대화를 이끌어내기에는 구조적 한계가 명확합니다.

현재 시스템 프롬프트 (Before)

// lib/ai/prompts/chat-prompts.ts (현재)

2. 최신 연구 리뷰

프롬프트 엔지니어링 기법의 진화

Role Prompting (2022)    ↓ Few-Shot Chain-of-Thought (2022~2023)    ↓ Prompt Chaining + 구조화 (2023~2024)    ↓ 메타프롬프팅 + 동적 컨텍스트 주입 (2024~2025)    ↓ 에이전트 오케스트레이션 (2025~현재)

메타프롬프팅의 핵심 원칙

  • 구조화된 섹션 분리: 역할 / 행동 지침 / 제약 조건 / 예시를 명확히 분리하여 모델이 각 섹션을 독립적으로 처리하도록 유도
  • 동적 컨텍스트 주입: {level}, {userName}, {recentBooks} 같은 변수를 런타임에 삽입하여 개인화 극대화
  • 계층적 지시 우선순위: 안전 가드레일 > 핵심 정체성 > 사용자 수준 맞춤 > 스타일 가이드 순으로 명시적 우선순위 설정

독서 교육 AI 사례: 소크라테스식 스캐폴딩

하버드 교육대학원 및 카네기멜론 OLI 플랫폼 연구에 따르면, AI 튜터가 직접 답을 제공하는 것보다 소크라테스식 질문법으로 학습자 스스로 답을 발견하도록 유도할 때 학습 retention이 평균 42% 향상됩니다.

스캐폴딩 단계 질문 유형 예시
1단계 사실 확인 기억 / 회상 "이 책에서 가장 기억에 남는 장면은 뭐였어?"
2단계 해석 분석 / 이유 "왜 그 장면이 기억에 남았다고 생각해?"
3단계 연결 적용 / 연관 "그 경험이 네 일상과 연결되는 부분이 있어?"
4단계 평가 종합 / 판단 "이 책을 읽고 나서 생각이 달라진 게 있어?"

ZPD(근접발달영역) 이론 적용: 비고츠키의 ZPD 개념에 따라 사용자의 현재 독서 수준보다 한 단계 위의 질문을 제공하여 도전감과 성취감을 동시에 경험하게 합니다. 책 권수 기반으로 수준을 자동 판별합니다.

동기부여 이론: 자기결정이론(SDT)

Deci & Ryan의 자기결정이론(Self-Determination Theory)은 내재적 동기 유발의 3가지 심리적 욕구를 정의합니다. 독서친구 챗봇은 이 3가지 욕구를 대화 전략에 내재화합니다.

자율성 (Autonomy)
사용자가 읽을 책, 대화 방향, 모드를 직접 선택. "어떤 이야기를 하고 싶어?" 형태의 열린 질문
유능감 (Competence)
적절한 난이도의 질문, 성취 시 구체적 칭찬, 점진적 기능 공개(Lv.1~3)로 성취 경험 제공
관계성 (Relatedness)
장기 기억 활용, 이름 호칭, 이전 대화 참조로 "나를 기억하는 친구" 느낌 제공
Gain-framing 적용
"읽지 못한 책" 대신 "읽은 책으로 얻은 것" 강조. 손실 회피보다 성취 강조로 긍정 정서 유발

아동·청소년 안전 및 교육 AI 윤리

  • 도메인 한정 원칙: 교육 AI는 설계 목적 도메인 외 요청을 명확히 거절해야 하며, 거절 시 대안을 제시해야 합니다 (EU AI Act Art. 13)
  • 숙제 대필 방지: 독후감·요약 직접 작성 요청 시 거절하고 작성 방법을 안내하는 스캐폴딩 방식 채택
  • 불확실성 솔직 인정: "모른다"고 솔직히 말하는 AI가 장기적으로 더 높은 신뢰를 얻음 (Stanford HAI 연구, 2024)
  • 개인정보 최소 수집: 이름·독서 기록 외 민감 정보 수집하지 않음, 대화 로그는 사용자가 삭제 가능

게이미피케이션 및 참여 설계

  • 퀴즈 모드: "책 내용 퀴즈" 대화 모드로 독서 내용 점검, 자연스러운 복습 유도
  • 점진적 기능 공개: 처음에는 심플한 UI → 이용 횟수 증가에 따라 고급 기능(토론 모드, 코칭 모드) 활성화
  • 대화 모드 전환: 사용자가 원하는 상호작용 유형을 명시적으로 선택 가능 (추천 / 토론 / 코칭 / 퀴즈)
  • 메시지 피드백: 좋아요/싫어요 반응으로 프롬프트 자동 개선 데이터 수집

3. 고도화 전략 — 5단계 Phase 로드맵

Phase 1
프롬프트 고도화
임팩트: 최상 난이도: 낮음 DB 변경 없음

시스템 프롬프트를 6섹션 구조로 재설계합니다. 코드 변경만으로 즉시 적용 가능하며 가장 높은 ROI를 제공합니다. 사용자의 총 독서 권수를 기준으로 3단계 수준(beginner / steady / passionate)을 자동 판별하여 톤·길이·질문 깊이를 동적으로 조정합니다.

프롬프트 6섹션 구조

  1. 핵심 정체성: AI 투명성, 도메인 범위, 핵심 목표 정의
  2. 소크라테스식 스캐폴딩: 4단계 질문 전략, 대화 규칙 (질문 1개 제한)
  3. 사용자 수준별 맞춤: beginner(0~5권) / steady(6~20권) / passionate(21권+) 세분화
  4. 감정 인식 및 공감: 5가지 감정 패턴 감지 및 대응 전략
  5. 안전 가드레일: 도메인 한정 / 숙제 대필 방지 / 불확실성 인정 / 개인정보 / 민감 주제
  6. Few-Shot 예시: 4가지 시나리오별 이상적 응답 패턴 시범

사용자 수준 자동 판별 로직

// lib/ai/prompts/chat-prompts.ts
function getUserLevel(bookCount: number): 'beginner' | 'steady' | 'passionate' {
  if (bookCount <= 5) return 'beginner';
  if (bookCount <= 20) return 'steady';
  return 'passionate';
}

동적 퀵 액션 생성 로직

// lib/ai/quick-actions.ts
interface QuickActionContext {
  recentBooks: string[];
  currentBook: string | null;
  lastSession: Date | null;
  bookCount: number;
}

function buildDynamicQuickActions(ctx: QuickActionContext): QuickAction[] {
  const actions: QuickAction[] = [];

  if (ctx.currentBook) {
    actions.push({
      label: `"${ctx.currentBook}" 이야기해줘`,
      mode: 'discuss',
    });
  }

  if (ctx.recentBooks.length > 0) {
    actions.push({
      label: `최근 읽은 책 추천 이어받기`,
      mode: 'recommend',
    });
  }

  if (!ctx.lastSession || daysSince(ctx.lastSession) >= 3) {
    actions.push({
      label: '독서 습관 점검해줘',
      mode: 'coaching',
    });
  }

  // 기본 액션 보충
  if (actions.length < 4) {
    actions.push(...DEFAULT_QUICK_ACTIONS.slice(0, 4 - actions.length));
  }

  return actions.slice(0, 4);
}

- reading_preference: 선호 장르, 싫어하는 장르, 독서 스타일

- goal: 명시적 독서 목표 (권수, 기간, 장르)
- emotion: 현재 독서에 대한 감정 상태 (슬럼프, 열정, 피로 등)
- context: 기타 개인 맥락 정보

출력 형식 (JSON 배열):
[
  { "type": "reading_preference", "content": "..." },
  { "type": "goal", "content": "..." }
]

추출할 정보가 없으면 빈 배열 [] 반환.
`;

  • 기대: 시스템 프롬프트에 reading_preference 메모리 주입됨
  • 검증: AI 응답이 추리소설 관련 컨텍스트를 자연스럽게 반영

시나리오 6: 감정 인식 — 좌절 감지

  • 조건: "이 책 진짜 어려워서 포기하고 싶어"
  • 기대: 공감 → 정상화 → 작은 성취 상기 순서로 응답
  • 검증: 즉각적 해결책 제시 대신 감정 인정 문장이 첫 문장으로 등장

시나리오 7: 대화 모드 전환

  • 조건: 사용자가 quiz 모드 선택 + "어린왕자" 컨텍스트
  • 기대: "어린왕자"에 관한 OX 또는 선택형 퀴즈 생성
  • 검증: 퀴즈 형태(질문 + 선택지 or OX) 구조 확인, 정답 바로 제시하지 않음
