## 1. 현재 기능 현황

### AI 독서 리포트란?

Habitree Reading Hub의 AI 독서 리포트는 사용자의 독서 기록을 분석해 개인화된 인사이트를 생성하는 기능이다.

| 항목 | 내용 |
|------|------|
| **분석 대상** | 최근 50개 독서 기록 |
| **생성 결과** | 6개 섹션 마크다운 리포트 |
| **공유 방식** | 고유 UUID 링크 `/share/reports/{shareId}` |
| **카카오 공유** | 카카오톡 링크 공유 지원 |
| **공개 데이터** | 책 제목·저자·표지, 리포트 본문, 독서 기록 (선택) |
| **공유 페이지** | 히어로 + Bento Grid + 공개 기록 목록 + 앱 유도 CTA |
| **DB 테이블** | `ai_generated_reports` (`is_public` + `include_notes` 토글) |

### 현재 리포트 6개 섹션

1. 독서 패턴 분석
2. 선호 장르/주제
3. 독서 속도와 집중도
4. 인상 깊은 책 하이라이트
5. 성장 영역 분석
6. 다음 독서 추천

### 장면 1: 처음 공유 리포트를 보았을 때

*배경: 카카오톡으로 친구에게 리포트 링크가 공유됨. 각자 링크를 열어보는 상황.*

---

**📚 독서인:**
"와, 이거 내 연간 독서 리포트잖아. 시각적으로 꽤 예쁘게 나왔네. 내가 SF를 이렇게 좋아하는 줄 몰랐는데, AI가 잡아냈어. 근데... 이걸 공유해서 뭘 얻는 거지? 그냥 '나 책 많이 읽었어'를 자랑하는 건가?"

**📵 비독서인:**
"(링크 열어보며) 어, 이게 뭐야? 독서 리포트? 친구가 올해 책을 28권 읽었다고? 대단하긴 한데... 그래서 나한테 뭘 해달라는 거지? 나보고 읽으라고? 솔직히 이 페이지 10초 보다가 닫았어."

**🌱 예비독서인:**
"(천천히 스크롤하며) 오 신기하다. 이 사람이 읽은 책들 제목이 보이네. 《원씽》, 《아주 작은 습관의 힘》... 어, 나도 이 책 읽고 싶었는데. 근데 어디서 사지? 클릭하면 살 수 있나? (눌러보지만 링크가 없음) 아, 아무것도 없네."

**🏪 서점인:**
"(업무 중 링크를 봄) 독서 리포트를 공유한다고? 흥미롭네. 이 사람이 읽은 책 목록을 보니 베스트셀러도 있고 독립출판물도 있어. 만약 이 리포트에 '저자 사인본 구매' 링크가 있었다면 우리 가게 트래픽이 됐을 텐데. 근데 지금은 아무 연결도 없어."

**📦 유통인:**
"(마케팅 시각으로) 이 기능... 데이터 관점에서 흥미롭네. 특정 책이 몇 번이나 리포트에 등장하는지 알 수 있다면 베스트셀러 예측 지표가 될 수도 있겠어. 근데 지금은 그 데이터가 아예 없고, 공개 피드도 없어. 아쉽다."

**✍️ 저자:**
"(알림을 통해 발견) 누군가 내 책을 읽고 리포트를 공유했구나. 어떻게 느꼈는지 궁금한데... 리포트에 내 책이 언급된 부분을 찾아보려니 전체를 다 읽어야 해. 독자가 내 책에 대해 뭘 생각하는지 한눈에 보고 싶은데."

### 장면 2: 기능의 가능성과 한계 토론

*배경: 6명이 한 자리에 모여 리포트 공유 기능에 대해 토론하는 상황.*

---

**🌱 예비독서인:**
"솔직히 말하면, 이 페이지에서 제일 궁금한 건 '저 사람이 읽은 책들 어떻게 사지?'예요. 근데 아무 링크가 없으니까 그냥 구글 검색해야 하잖아요. 독서 리포트가 책 구매로 이어질 수 있는 가장 자연스러운 순간인데, 그걸 놓치고 있어요."

**🏪 서점인:**
"맞아요. 독서 리포트는 사실 굉장히 강력한 구매 유발 콘텐츠예요. '이 사람이 읽고 감동받은 책'이라는 맥락이 붙으면 일반 광고보다 훨씬 신뢰도가 높거든요. 근데 지금은 그 가능성을 완전히 날리고 있어요."

**📚 독서인:**
"저도 공유하는 입장에서 솔직히 말하면, '와 대단하다'는 반응을 원하긴 해요. (웃음) 근데 그게 다예요. 공유하고 나서 친구가 '나도 이 앱 써보고 싶다'고 하면 뿌듯할 것 같은데, 지금 CTA가 너무 약한 것 같아요. '앱 다운로드' 버튼 하나만 있는데, 비독자한테는 동기부여가 없잖아요."

**📵 비독서인:**
"저한테는 솔직히 이 리포트가 '나는 책을 안 읽는 루저야'라는 느낌을 줘요. (웃음) 책 많이 읽는 사람의 자랑처럼 보이거든요. 만약 '당신도 한 달에 책 1권으로 이런 변화를 경험할 수 있어요'라는 메시지가 있었다면 달랐을 것 같아요."

**📦 유통인:**
"데이터 관점에서 가장 아쉬운 건 공개 피드가 없다는 거예요. 지금은 공유해도 그 리포트가 어딘가에 쌓이지 않잖아요. 만약 공개 피드가 생기면 '이번 달 가장 많이 읽힌 책', '이 책을 읽은 사람들의 공통점' 같은 집계 데이터가 나올 수 있어요. 출판사 입장에서는 황금 같은 마케팅 인사이트죠."

**✍️ 저자:**
"저는 독자 피드백을 정말 갈망해요. SNS에서 '이 책 좋아요'라는 댓글은 많은데, 실제로 어떻게 읽었는지, 어떤 챕터가 인상 깊었는지는 잘 몰라요. 만약 AI 리포트에서 내 책이 언급된 내용만 저에게 알림이 간다면... 그건 정말 가치 있는 독자 인사이트가 될 것 같아요."

**📚 독서인:**
"그리고 인스타 공유! 지금은 카카오톡만 되는데, 인스타 스토리용 이미지가 있으면 확산력이 엄청 달라질 거예요. 텍스트 리포트를 시각적인 카드로 만들어서 '올해 나의 독서 결산'으로 공유하면 완전 바이럴될 것 같은데."

**🌱 예비독서인:**
"맞아요! 연말에 스포티파이 연간 결산처럼요. 독서 버전 '독서 레시피' 같은 거. 그게 있으면 저도 앱 설치할 것 같아요."

### 장면 3: "이런 게 있으면 좋겠다" 아이디어 제안

*배경: 각자 리포트 공유 기능에 대해 하나씩 원하는 기능을 제안하는 상황.*

---

**📚 독서인 (독자 경험 최적화 관점):**
"리포트를 공유할 때 '하이라이트 카드' 기능이 있으면 좋겠어요. 예를 들어, 내가 올해 읽은 책 중 베스트 3를 뽑아서 인스타 스토리 비율(1:1이나 4:5)로 예쁜 이미지 카드를 만들어주는 거예요. 'AI가 분석한 나의 독서 성향' 같은 문구도 자동으로 들어가고요. 지금처럼 링크만 공유하는 것보다 훨씬 임팩트 있을 것 같아요."

**📵 비독서인 (비사용자 유인 관점):**
"저 같은 비독자를 위한 '책 핵심 요약 카드' 기능이 있으면 어때요? 리포트를 보다가 관심 가는 책 제목을 클릭하면, AI가 그 책의 핵심 인사이트를 3문장으로 요약해주는 거예요. '5분 만에 이 책의 핵심 배우기' 같은 느낌으로요. 비독자가 독서에 진입하는 가장 낮은 허들이 될 수 있을 것 같아요. 그리고 '나도 이 책 읽어볼게'라는 전환이 자연스럽게 생기고요."

**🌱 예비독서인 (책 발견 및 구매 관점):**
"리포트에 있는 책마다 구매 링크가 자동으로 달렸으면 해요. ISBN 기반으로 알라딘, 교보문고, 예스24 딥링크가 바로 연결되면 좋겠어요. 리포트 보다가 '오, 이 책 읽고 싶다'는 순간이 오는데, 그 순간 바로 살 수 있어야 하잖아요. 지금은 구글 검색 → 서점 검색 → 구매로 3단계인데, 1단계로 줄일 수 있어요."

**🏪 서점인 (판매 전환 관점):**
"서점 파트너십 기능이요. 특정 지역 독립서점과 연동해서, 리포트에 있는 책들이 해당 서점에 있으면 '가까운 서점에서 보기' 버튼이 뜨는 거예요. 대형 온라인 서점과 달리 독립서점은 큐레이션과 커뮤니티가 강점이잖아요. 독서인과 서점을 연결하는 허브 역할을 Habitree가 할 수 있다고 봐요. 서점 입장에서는 제휴 수수료도 낼 수 있고요."

**📦 유통인 (데이터 및 마케팅 관점):**
"공개 리포트 피드와 집계 데이터요. 월간 '이 책이 가장 많이 리포트에 등장했어요' 같은 트렌딩 지표. 출판사가 이 데이터를 구독하면 마케팅 예산을 훨씬 효율적으로 쓸 수 있어요. 또 '이 책을 읽은 사람들이 다음에 읽은 책'같은 연관 도서 데이터는 추천 알고리즘의 핵심이 될 수 있고요. 유통사 관점에서 Habitree가 독서 데이터 플랫폼으로 성장할 수 있는 핵심 자산이에요."

**✍️ 저자 (창작자 관점):**
"저자 대시보드를 만들어주세요. 내 책이 언제, 얼마나 읽혔는지, 독자들이 AI 리포트에서 내 책에 대해 어떤 말을 했는지 볼 수 있는 곳이요. 지금은 판매량 데이터는 있지만 '어떻게 읽혔는지' 데이터는 전혀 없어요. 독자가 내 책을 어떤 맥락에서 인상 깊게 기억하는지 알면, 다음 책을 쓸 때 엄청난 참고가 돼요. 저자 입장에서는 인세보다 더 가치 있는 피드백이에요."

## 4. 도출된 기능 후보 목록

### 단기 (Quick Wins, 1~2 sprint)

> 기존 아키텍처에서 빠르게 구현 가능한 기능

#### QW-1. 리포트 하이라이트 카드 생성
- **설명**: 리포트의 핵심 요소(올해 읽은 책 수, 베스트 책 3권, 독서 성향)를 인스타그램용 이미지 카드로 생성
- **비율**: 1:1 (스퀘어), 4:5 (포트레이트), 9:16 (스토리)
- **기술**: `html2canvas` 또는 `@vercel/og` API로 이미지 생성
- **대상**: 독서인의 소셜 공유 욕구 충족
- **기대 효과**: 바이럴 확산, 신규 유저 유입

#### QW-2. 책 구매 링크 자동 삽입
- **설명**: 리포트에 등장하는 책들에 알라딘/교보문고 딥링크 자동 연결
- **방법**: ISBN 기반 → 각 서점 URL 패턴으로 자동 생성
  ```
  알라딘: https://www.aladin.co.kr/search/wsearchresult.aspx?SearchWord={ISBN}
  교보:   https://product.kyobobook.co.kr/detail/{ISBN}
  yes24:  https://www.yes24.com/Product/Search?SearchWord={ISBN}
  ```
- **대상**: 예비독서인의 즉각 구매 전환
- **기대 효과**: 구매 전환율, 제휴 수익 (추후)

#### QW-3. 공유 리포트 조회수 표시
- **설명**: 리포트 공유 시 조회수 카운터 표시 (`n명이 읽었어요`)
- **DB**: `ai_generated_reports.view_count` 컬럼 추가
- **대상**: 독서인의 공유 동기 강화
- **기대 효과**: 공유 지속성 향상

#### QW-4. 리포트 공유 후 반응 기능
- **설명**: 공개 리포트에 이모지 반응 (👏 멋지다, 📚 나도 읽어볼게, 💡 인사이트 얻었어)
- **DB**: `report_reactions` 테이블
- **대상**: 독서인, 예비독서인
- **기대 효과**: 소셜 참여도 향상, 앱 재방문 유도

---

### 중기 (Mid-term, 1~2 months)

> 새로운 데이터 구조나 기능이 필요한 기능

#### MT-1. 공개 리포트 피드 (탐색 페이지)
- **설명**: `/explore/reports` - 공개된 리포트 모아보기 (최신/트렌딩/장르별)
- **필터**: 기간, 장르, 독서량 구간
- **대상**: 예비독서인의 책 발견, 비독자의 독서 문화 경험
- **기대 효과**: 서비스 체류시간, 신규 유저 진입점

#### MT-2. 독서 통계 인포그래픽 삽입
- **설명**: 리포트 내 시각적 차트 추가 (월별 독서량 바 차트, 장르 파이 차트, 독서 속도 히스토그램)
- **기술**: Recharts 기반 SVG → 공유 이미지 포함
- **대상**: 독서인의 자기 이해, 시각적 공유 콘텐츠
- **기대 효과**: 리포트 체류시간, 공유 품질 향상

#### MT-3. 저자/출판사 공식 뱃지
- **설명**: 리포트에 언급된 책의 저자/출판사가 등록된 경우 공식 뱃지 표시
- **모델**: 저자 계정 등록 → 인증 → 뱃지 부여
- **대상**: 저자의 서비스 참여 유도
- **기대 효과**: 저자 커뮤니티, B2B 파트너십 시작점

#### MT-4. 비독자용 '책 핵심 3줄 요약' 카드
- **설명**: 리포트 내 책 클릭 시 AI가 생성한 3문장 핵심 요약 표시
- **기술**: Claude API로 책 제목+장르 기반 요약 생성 (캐싱 필수)
- **대상**: 비독자, 예비독자의 책 진입 장벽 낮추기
- **기대 효과**: 비독자 전환율, 구매 의향 증가

#### MT-5. 리포트 '이 책도 읽어보세요' 추천
- **설명**: 리포트 하단에 AI 기반 유사 책 추천 (읽은 책들의 패턴 분석)
- **기술**: 리포트 생성 시 추천 목록도 함께 생성 (Claude API)
- **대상**: 독서인의 다음 책 발견, 예비독자의 큐레이션 니즈
- **기대 효과**: 앱 재사용률, 독서 지속성

---

### 장기 (Long-term, 3~6 months)

> 새로운 비즈니스 모델이나 파트너십이 필요한 기능

#### LT-1. 저자 대시보드
- **설명**: 저자용 별도 뷰 - 내 책이 언급된 리포트 수, 독자 반응, 인용 문구
- **모델**: 저자 계정 등록 → 저자 ID로 책 연결 → 리포트 언급 집계
- **대상**: 저자, 출판사 마케팅 담당
- **기대 효과**: B2B 수익 모델 (저자 인사이트 구독), PR 채널

#### LT-2. 서점/출판사 파트너십 API
- **설명**: 리포트 내 도서 클릭 → 파트너 서점으로 리다이렉트 → 수수료 정산
- **모델**: 제휴 링크 (Affiliate) 기반, 독립서점 우선
- **대상**: 서점인, 유통인
- **기대 효과**: 수익 다각화, 오프라인 서점 생태계 연결

#### LT-3. 공개 독서 트렌드 리포트
- **설명**: 월간/연간 Habitree 유저들의 독서 트렌드 집계 리포트 공개
  - 이달의 독서 베스트셀러
  - 연령대별 선호 장르
  - 지역별 독서 패턴
- **대상**: 유통인, 출판사, 언론 (PR용)
- **기대 효과**: 브랜드 미디어화, 언론 노출, 출판사 파트너십

#### LT-4. AI 리포트 기반 도서 추천 엔진
- **설명**: 전체 사용자 리포트 데이터 분석 → 협업 필터링 기반 추천
  - "당신과 독서 성향이 비슷한 사람들은 이 책을 읽었어요"
  - "이 책을 읽은 사람들의 다음 책"
- **기술**: 임베딩 기반 유사도 검색 (pgvector 활용)
- **대상**: 전체 사용자
- **기대 효과**: 앱 핵심 가치 강화, 체류시간 증가

#### LT-5. SNS 자동 공유 예약
- **설명**: 독서 완료 시 "이 책 읽었어요" 카드를 인스타/X/쓰레드에 예약 공유
- **기술**: 소셜 API 연동 + 공유 이미지 자동 생성
- **대상**: 독서인의 독서 문화 확산
- **기대 효과**: 오가닉 마케팅, 신규 유저 유입

## 7. 구현 시 고려사항

### 기술 제약

- **이미지 생성**: 서버사이드에서 `@vercel/og` 사용 권장 (클라이언트 `html2canvas`는 CORS 이슈 가능)
- **책 구매 링크**: ISBN 기반 딥링크는 서점마다 URL 패턴이 다름, 테스트 필요
- **공개 피드 성능**: 페이지네이션 + Supabase RLS 정책 설계 중요
- **AI 요약 캐싱**: 동일 책의 요약은 DB에 캐싱하여 API 비용 절감

### 개인정보 및 보안

- 공유 리포트의 기록(독서 노트) 포함 여부는 사용자 선택 유지
- 저자 대시보드는 집계 데이터만 공개, 개별 독자 식별 불가
- 공개 피드의 RLS: `is_public = true`인 리포트만 노출

### UX 원칙

- 공유 페이지는 비로그인 사용자 최적화 (앱 없어도 가치 있게)
- CTA는 강요가 아닌 자연스러운 유입 유도
- 비독자에게는 '부담 없는 독서 시작' 메시지

## 8. 결론

리포트 공유 기능은 현재 **독서인의 자기 표현 도구**에 머물고 있으나, 이해관계자 분석을 통해 다음을 확인했다:

1. **예비독자**: 가장 직접적인 전환 기회 (책 발견 → 구매 → 앱 가입)
2. **비독자**: 바이럴 확산의 핵심 (리포트를 보고 독서에 관심 갖게 되는 계기)
3. **저자/출판사**: B2B 수익 모델의 시작점 (독자 인사이트에 대한 수요 존재)
4. **서점**: 오프라인-디지털 연결의 새로운 채널

가장 임팩트 있고 빠른 첫 걸음은 **하이라이트 카드 생성 (QW-1)** 과 **책 구매 링크 자동 삽입 (QW-2)** 이다. 두 기능만으로 바이럴 잠재력과 구매 전환 퍼널을 동시에 열 수 있다.
