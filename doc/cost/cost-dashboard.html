04 원인과 함정

왜 생겼고, 왜 6개월간 아무도 몰랐는가.

⚠️ 리비전 설정과 서비스 설정은 별개다

Cloud Run의 최소 인스턴스는 두 군데에 있다. 배포 페이지의 "버전 확장"은 이미 0이었고, 진짜 범인은 서비스 상세 헤더 우측 연필 아이콘(툴팁 "서비스 수준 확장 설정 수정") 안에 숨은 서비스 수준 설정 1이었다.

새 리비전을 배포해도 이 값은 바뀌지 않는다. 배포 페이지만 보면 "최소 0인데 왜 과금되지?"에서 막힌다.

🔍 산술 검증

1,927,221 vCPU-초 ÷ 22일
  = 87,601초/일

1 vCPU × 24시간
  = 86,400초/일

→ 오차 1.4%
→ 인스턴스 1개 상시 기동 확정

gcloud run services update \

  • 콜드스타트 수 초 발생 (관리자 기능이라 허용)
  • 코드·기능 변경 없음

💡 요청 기반 과금이어도 min-instance는 예외

"요청이 없으면 0원"이라는 인식이 이 사고를 6개월간 가렸다. min-instance는 idle 상태에도 CPU·메모리가 청구된다. 무료 티어 월 180,000 vCPU-초를, 상시 인스턴스 1개는 약 2,592,000초로 14배 초과 소진한다.
