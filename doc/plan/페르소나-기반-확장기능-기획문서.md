# 페르소나 대화 기반 확장 기능 기획문서

**문서 성격**: 유입·확장 기능 기획 (승덕·진수·동혁 3인 페르소나 대화 산출물 반영)  
**관련 문서**: [doc/ReadTree-PRD.md](../ReadTree-PRD.md), [doc/question/페르소나-대화-및-프롬프트-기록.md](../question/페르소나-대화-및-프롬프트-기록.md)  
**최종 수정**: 2026-02

## 1. 개요

### 1.1 목적

- **승덕**(책을 전혀 읽지 않음), **진수**(어쩌다 읽음), **동혁**(많이 읽음) 3가지 관점의 페르소나 대화를 통해 도출한 **서비스 문제점**과 **유입 방안**을 반영한 확장 기능을 기획한다.
- 현재 타깃이 "꾸준히 책을 읽고 기록하는 독자"에 치우쳐 있어, 비독자·경량 독자의 진입 경로가 부족한 점을 보완한다.

### 1.2 페르소나 요약

| 페르소나 | 특성 | 현재 서비스와의 괴리 |
|----------|------|----------------------|
| 승덕 | 책을 전혀 읽지 않음. 유튜브·인스타·카톡에 문장 저장 | "책 기록"만 있으면 할 행동 없음 |
| 진수 | 1년에 2~3권 수준, 읽는 동안 기록할 생각을 잘 안 함 | 첫 사용이 무겁고 "지금 당장 기록" 압박 |
| 동혁 | 책을 많이 읽고 기록하는 핵심 유저 | 주제·키워드 검색, 모임 단위 유입 부족 |

## 2. 확장 기능 기획

### 2.1 문장 수집(책 없이 저장) 기능

**배경**: 책을 읽지 않는 승덕, 아직 책을 연결하지 않은 진수도 "인상 깊은 한 줄"을 저장할 수 있어야 유입·재방문이 생긴다.

**기능 요약**:

- **책 없이 문장만 저장**할 수 있는 플로우 제공.
- 출처는 선택 입력 (유튜브, 인스타, 기사, 책 등). 나중에 해당 문장을 책과 연결하는 옵션 제공.
- 첫 가입/첫 방문 시 "올해 읽을 책 수" 대신 **"오늘/이번 주 본 문장 한 줄 넣어보기"**를 권장 진입점으로 사용.

**요구사항**:

- [ ] 노트(기록) 생성 시 "책 없음" 또는 "나중에 책 연결" 옵션 지원
- [ ] 데이터 모델: `notes`에 `book_id` nullable 또는 "문장만"용 별도 플래그/타입 검토
- [ ] 온보딩/첫 화면: "문장 한 줄만 넣어보기" CTA 및 단일 입력 플로우

**참고**: PRD의 "기록 통합"은 책 단위가 전제이므로, "문장 수집"을 서브 경로로 확장하는 형태로 설계.

---

### 2.2 가벼운 첫 사용(경량 온보딩) 플로우

**배경**: 진수처럼 가끔 읽는 사용자는 "책 검색 → 책 추가 → 기록"이 부담이 되어 이탈할 수 있다.

**기능 요약**:

- **첫 행동을 "기록 1개 추가"**로 단순화. 책 선택은 선택 사항으로 둠.
- 예: "오늘 본 문장 한 줄" 입력 → 저장 → 이후 "이 문장을 책과 연결할까요?" 제안.
- 목표 설정("올해 읽을 책 수")은 첫 기록 이후 또는 스킵 가능하게 배치.

**요구사항**:

- [ ] 홈/대시보드: 미기록 사용자에게 "문장 한 줄 넣기" 강조
- [ ] 온보딩: "목표 설정" 단계를 "문장 1개 넣기" 뒤로 이동 또는 스킵 옵션
- [ ] 문장 저장 후: "책과 연결하기" 추천 UI (검색/선택)

---

### 2.3 주제·키워드 기반 검색/정리

**배경**: 동혁처럼 많이 읽는 사용자는 여러 책에 걸친 주제(예: 자유, 시간, 관계)로 기록을 묶어보고 싶어 한다.

**기능 요약**:

- **태그/주제**로 기록 검색·필터링.
- (향후) 여러 책에 걸친 **주제별 모아보기** 또는 컬렉션.

**요구사항**:

- [ ] 검색 옵션: 기존 책 제목·날짜·전문 검색에 **태그/주제** 조건 추가
- [ ] 기록 입력 시 태그/주제 입력 필드 (선택)
- [ ] "주제별 모아보기" 화면 (목록/필터): Post-MVP 검토

**참고**: PRD 4.1.4 검색 옵션에 "주제/태그로 검색" 명시됨. 구현 여부 및 UX만 확인·보강.

---

### 2.4 독서모임·커뮤니티 단위 유입

**배경**: 이미 독서모임이 카톡·노션으로 운영 중이면 "한 명씩 이전"은 비용이 크다. 모임 단위로 이전할 수 있으면 유입이 쉽다.

**기능 요약**:

- **모임(그룹) 단위 초대**: 링크 하나로 모임 생성 + 멤버 일괄 초대 또는 가입 유도.
- 독서모임·북클럽·동아리와의 제휴 시 "우리 모임 기록은 ReadTree로" 전환 지원.

**요구사항**:

- [ ] 그룹 생성 시 "초대 링크" 생성 및 공유
- [ ] 초대 링크로 진입 시 "모임 가입 + 첫 기록" 단순 플로우
- [ ] (운영) 독서모임·크리에이터 제휴 시 모임 단위 온보딩 가이드 문서

---

### 2.5 공유 카드 브랜딩 및 역유입

**배경**: SNS에서 "인상 깊은 문장 카드"가 노출될 때 출처가 있으면, 승덕·진수도 "그거 어디서 만드나?" 하고 유입될 수 있다.

**기능 요약**:

- 공유 이미지(카드뉴스)에 **ReadTree 로고/워터마크** 및 **"여기서 만들었어요"** 링크 포함.
- 다양한 페르소나의 문장이 노출되도록 (책을 많이 읽는 사람 위주가 아닌) 샘플/추천 노출 전략 검토.

**요구사항**:

- [ ] 공유 카드 생성 시 로고/워터마크·서비스 URL 옵션 (기본 on 권장)
- [ ] "이 카드 만들기" 랜딩: 공유 URL에서 서비스 소개 + 가입/체험 유도
- [ ] (마케팅) 인스타/유튜브 등에서 "가끔 읽는 사람·비독자" 문장 예시 활용

## 3. 우선순위 제안

| 순위 | 확장 기능 | 기대 효과 | 난이도(참고) |
|------|-----------|-----------|--------------|
| 1 | 가벼운 첫 사용(경량 온보딩) | 진수·승덕 진입 장벽 하락 | 중 |
| 2 | 문장 수집(책 없이 저장) | 비독자·경량 독자 유입 | 중 (데이터 모델 검토) |
| 3 | 공유 카드 브랜딩·역유입 | SNS 경유 유입 | 하 |
| 4 | 독서모임 단위 초대 | 모임·커뮤니티 유입 | 중 |
| 5 | 주제·키워드 검색/정리 | 동혁 만족도·재사용률 상승 | 중~고 |

## 4. 비기능·운영 고려사항

- **데이터 모델**: "책 없이 문장만" 저장 시 `notes` 스키마·RLS·인덱스 영향 검토 필요. `doc/database/DATA_MODEL.md` 및 마이그레이션 규칙 준수.
- **메시지 일관성**: 랜딩·온보딩 문구를 "책 기록"뿐 아니라 "인상 깊은 문장 수집"으로 확장해 포지셔닝을 넓힐 수 있음.
- **측정**: 유입 경로별(문장만 저장 유저 vs 책 연결 유저) 가입·재방문 지표 정의 권장.
