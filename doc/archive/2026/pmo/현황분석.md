# ReadTree 서비스 현황 종합 분석서

**작성일:** 2026-02-19
**버전:** 1.0
**대상 서비스:** ReadTree (Habitree Reading Hub v4.0.0)

---

## 1. 서비스 개요

### 1.1 기술 스택 및 규모

| 항목 | 현황 |
|------|------|
| 프레임워크 | Next.js 15 + React 19 |
| 백엔드/DB | Supabase (PostgreSQL + RLS) |
| 배포 | Vercel |
| 라우트 수 | 47+ |
| 컴포넌트 수 | 220+ |
| DB 테이블 수 | 31 |
| 서버 액션 수 | 150+ (18개 액션 파일) |
| 마이그레이션 | 60+ SQL 파일 |
| 인증 | Supabase Auth (카카오, Google, GitHub) |
| 다국어 | 한국어/영어 |
| 상태 관리 | Zustand (2 stores) |

### 1.2 핵심 기능 모듈

| 모듈 | 주요 기능 | 관련 라우트 |
|------|----------|------------|
| 책 관리 | 네이버 API 검색, 책 추가/편집, 진행률 관리 | `/books`, `/books/search`, `/books/[id]` |
| 독서 노트 | 인용, 메모, 사진, 필사(OCR), 진행률 기록 | `/notes`, `/notes/new`, `/notes/[id]` |
| 대시보드 | 히어로 섹션, 이어읽기, 주간 진행, 온보딩 | `/` (메인) |
| 타임라인 | 월별 기록 시각화, 정렬 | `/timeline` |
| 통계 | 독서 통계, 월간 캘린더, 활동 분석 | `/stats` |
| 독서나무 | 포인트/레벨 시스템 (Lv.1~10), 나무 성장 | 대시보드 내장 |
| 독서모임 | 그룹 생성/참여, 초대링크, 공유 노트 | `/groups`, `/groups/[id]` |
| 페르소나 | 독서 성향 분석, 레이더 차트 | `/persona` |
| 검색 | 통합 검색, 페이지네이션 | `/search` |
| 공유 | 노트 공유, 책장 공유, OG 이미지 | `/share/notes/[id]`, `/share/bookshelves/[id]` |
| 프로필 | 사용자 설정, 계정 관리 | `/profile` |
| 온보딩 | 동의, 목표 설정, 튜토리얼, 체크리스트 | `/onboarding/*` |
| AI 채팅 | AI 독서 비서 | `/chat` |
| 기능 요청 | 사용자 피드백 게시판 | `/feature-requests` |
| 관리자 | 통계, OCR 설정, AI 설정 | `/admin/*` |

### 1.3 데이터 모델 하이라이트

- **reading_status enum**: `not_started`, `reading`, `completed`, `paused`, `rereading`
- **note_type enum**: `quote`, `photo`, `memo`, `transcription`, `progress`
- **포인트 시스템**: `point_transactions` 테이블, 레벨별 나무 이미지 (10단계)
- **소셜 기능**: `groups`, `group_members`, `group_books`, `group_shared_books`
- **개인화**: `user_personas` (독서 성향 분석), `user_book_relations` (책 간 관계)

## 2. 사용자 여정 6단계별 기능 인벤토리

### Stage 0: 발견 (Discovery)

사용자가 ReadTree를 처음 알게 되는 접점.

| 기능 | 구현 상태 | 설명 |
|------|----------|------|
| SEO | O | `app/robots.ts`, `app/sitemap.ts` 구현 |
| OG 이미지 | O | 노트/책장 공유 시 동적 OG 이미지 생성 |
| 공유 카드 | O | `share-note-card.tsx`, `simple-share-dialog.tsx` |
| 랜딩 페이지 | O | `landing-page.tsx` (히어로, 문제, 솔루션, 혜택, 사회적 증거, CTA 섹션) |
| About 페이지 | O | `/about` 라우트 |

**현황 평가**: SEO/OG 기본 인프라는 갖춰져 있으나, 검색 엔진 최적화 심화 작업(구조화 데이터, 키워드 전략) 미비.

### Stage 1: 탐색 (Exploration)

가입 전 서비스를 체험하는 단계.

| 기능 | 구현 상태 | 설명 |
|------|----------|------|
| 게스트 모드 | O | 비로그인 시 샘플 데이터로 대시보드 체험 |
| 샘플 데이터 | O | `app/actions/sample.ts` - 샘플 책/노트/통계 제공 |
| 게스트 배너 | O | `guest-banner-client.tsx` - 가입 유도 CTA |
| 샘플 책장 | O | `sample-bookshelf-content.tsx` |
| 샘플 노트 | O | `sample-notes-list.tsx`, `sample-notes-empty-state.tsx` |

**현황 평가**: 게스트 프리뷰 시스템이 잘 구축되어 있음. 샘플 데이터가 실제 사용 경험을 효과적으로 전달.

### Stage 2: 가입 (Registration)

계정을 만들고 초기 설정을 완료하는 단계.

| 기능 | 구현 상태 | 설명 |
|------|----------|------|
| 소셜 로그인 | O | 카카오, Google, GitHub (Supabase Auth) |
| 이메일 인증 | O | `/verify-email` 라우트 |
| 온보딩 동의 | O | `/onboarding/consent` - 개인정보 동의 |
| 목표 설정 | O | `/onboarding/goal` - 연간 독서 목표 |
| 튜토리얼 | O | `/onboarding/tutorial` - 기능 안내 |
| 에러 처리 | O | `app/(auth)/error.tsx` - 인증 에러 페이지 |

**현황 평가**: 소셜 로그인은 원활. 온보딩 프로세스 3단계(동의-목표-튜토리얼)가 명확하나, 가입 직후 "첫 행동"까지의 연결이 약함.

### Stage 3: 첫 행동 (Activation)

가입 후 핵심 가치를 처음 경험하는 단계.

| 기능 | 구현 상태 | 설명 |
|------|----------|------|
| 첫 책 추가 | O | 네이버 API 검색 → 원클릭 추가 |
| 첫 노트 작성 | O | 텍스트 입력 또는 OCR 사진 업로드 |
| 온보딩 체크리스트 | O | 5개 항목 (첫 책, 첫 노트, 나무 물주기, 목표 설정, 페르소나) |
| FirstNotePrompt | O | 노트 미작성 시 CTA 표시 |
| NoReadingBookCard | O | 읽는 책 없을 때 책 추가 유도 |
| 오늘의 할 일 | O | 상황별 미션 CTA (첫 행동/읽기/기록/완료) |

**현황 평가**: 온보딩 체크리스트 5개 항목이 한번에 노출되어 인지부하 유발 가능. 첫 책 추가의 검색 초기 화면이 비어있어 "무엇을 검색해야 하지?" 고민 발생.

### Stage 4: 습관화 (Retention)

반복적으로 서비스를 사용하며 습관을 형성하는 단계.

| 기능 | 구현 상태 | 설명 |
|------|----------|------|
| 연속 기록 (Streak) | O | 일별 기록 연속 카운트 + 불꽃 아이콘 |
| 나무 성장 | O | Lv.1~10 나무 이미지 + 포인트 시스템 |
| 주간 달성 | O | 7일 나뭇잎 지표 (기록 여부 시각화) |
| 이어읽기 카드 | O | 최근 읽던 책 최대 6권, 인라인 진행률 업데이트 |
| 진행률 편집 | O | 대시보드에서 클릭으로 페이지 수 즉시 수정 |
| 시간대별 메시지 | O | 아침/점심/저녁별 동기부여 메시지 |
| 월간 캘린더 | O | 일별 독서 활동 표지 표시 |
| 월간 요약 | O | 월별 독서 통계 카드 |

**현황 평가**: 스트릭, 나무 성장, 포인트 등 게이미피케이션 요소가 잘 설계됨. 다만, 활동이 없는 날의 Tertiary Zone이 `null`을 반환하여 사라지는 문제 존재.

### Stage 5: 확장 (Expansion)

소셜 기능을 활용하고 서비스 가치를 확산하는 단계.

| 기능 | 구현 상태 | 설명 |
|------|----------|------|
| 독서모임 | O | 그룹 생성, 초대 링크, 공유 노트, 멤버 역할 |
| 노트 공유 | O | 공개 링크 생성, OG 이미지 |
| 책장 공유 | O | 공개 책장 링크 |
| 기능 요청 | O | 사용자 피드백 게시판 |
| 프로필 공개 | O | `/profile/[id]` 공개 프로필 |

**현황 평가**: 독서모임 기본 기능은 갖춰져 있으나, 그룹 발견(탐색) 기능이 부족하고 바이럴 루프(초대 보상 등)가 없음.

## 3. 현재 잘 작동하는 것

### 3.1 게스트 프리뷰 시스템
- 비로그인 상태에서 샘플 데이터로 전체 대시보드 체험 가능
- `actions/sample.ts`에서 일관된 샘플 데이터 제공
- 게스트 배너로 자연스러운 가입 유도

### 3.2 다국어 지원
- `lib/i18n` 기반 한국어/영어 전환
- 모든 UI 텍스트가 번역 키로 관리됨
- `language-toggle.tsx` + `language-initializer.tsx`로 즉시 전환

### 3.3 다크 모드
- `theme-provider.tsx` 기반 시스템/라이트/다크 모드
- 모든 컴포넌트에 `dark:` 클래스 적용

### 3.4 모바일 반응형
- 모바일 우선 설계: 하단 네비게이션, FAB 스타일 노트 생성 버튼
- 대시보드 2열 그리드, 컴팩트 카드 레이아웃
- `touch-feedback.tsx`로 모바일 터치 피드백

### 3.5 진행률 인라인 편집
- 대시보드의 이어읽기 카드에서 진행률 바 클릭 시 즉시 페이지 수 수정
- 낙관적 업데이트(Optimistic Update) 적용
- 서버 동기화 실패 시 자동 롤백

### 3.6 EmptyState 컴포넌트 시스템
- 4가지 감정적 변형: `default`, `encouraging`, `celebratory`, `curious`
- 일관된 빈 상태 UI 패턴 (아이콘 + 메시지 + 다음 행동 힌트 + CTA)
- 재사용 가능한 컴포넌트 아키텍처

### 3.7 포인트/레벨 시스템
- 행동 기반 포인트 적립 (책 추가, 노트 작성, 연속 기록 등)
- 10단계 나무 성장 시각화 (실제 이미지)
- 온보딩 체크리스트와 연동된 보상 시스템

## 4. 개선 필요한 것: 5대 핵심 이탈 지점

### 4.1 Cold Start Gap: 책 0권에서 첫 책 추가까지의 전환 마찰

**현상**
- 가입 직후 대시보드에 `NoReadingBookCard`가 표시됨
- CTA가 "책 추가하기" 한 가지뿐 (검색 페이지로 이동)
- 사용자는 "어떤 책을 추가해야 하지?"라는 결정 마비(Decision Paralysis) 경험

**영향 범위**
- `components/dashboard/sections/continue-reading-card.tsx` - `NoReadingBookCard` 컴포넌트
- `components/dashboard/sections/home-hero-section.tsx` - 히어로 섹션의 이어읽기 영역

**데이터 포인트**
- `reading_status` enum에 `not_started`가 이미 존재하지만, 대시보드에서 "읽고 싶은 책"으로 활용되지 않음
- 검색 페이지(`/books/search`)로 이동해야만 책을 추가할 수 있음

### 4.2 Discovery Gap: 책 검색 초기 화면이 비어있음

**현상**
- `/books/search` 페이지 진입 시 검색어 입력 전까지 빈 화면
- 인기 도서, 추천 도서, 최근 트렌드 등 탐색 콘텐츠 부재
- 사용자가 능동적으로 키워드를 알고 있어야만 검색 가능

**영향 범위**
- `app/(main)/books/search/page.tsx`
- `components/search/search-results.tsx`

**기회 비용**
- 네이버 검색 API 연동이 이미 되어 있어, 인기 도서 목록이나 카테고리별 추천 추가가 기술적으로 가능
- 기존 사용자들이 많이 추가한 책 데이터 활용 가능 (단, RLS 정책 검토 필요)

### 4.3 Engagement Gap: 빈 상태 메시지가 기능적이고 중립적

**현상**
- `EmptyState` 컴포넌트에 4가지 감정적 변형(`encouraging`, `celebratory`, `curious`)이 정의되어 있으나, 실제 대부분의 페이지에서 `default`(중립) 변형만 사용
- 빈 상태 메시지가 "아직 데이터가 없습니다" 스타일의 기능적 문구
- 빈 상태를 격려와 탐험의 기회로 전환하는 감정적 설계가 미활용

**영향 범위**
- `/timeline` - 빈 타임라인
- `/stats` - 빈 통계 페이지
- `/notes` - 노트 없음 상태
- `/groups` - 그룹 미참여 상태
- `/bookshelves` - 빈 책장

**설계 자산**
- `EmptyState` 컴포넌트의 `variant`, `nextStepHint`, `illustrationSrc` 속성이 이미 구현되어 있어, 변형을 적용하는 것만으로 개선 가능

### 4.4 Onboarding Gap: 체크리스트 5개가 인지부하 유발

**현상**
- 온보딩 체크리스트가 5개 항목을 한번에 표시: 첫 책(35p), 첫 노트(25p), 나무 물주기(10p), 목표 설정(20p), 페르소나 탐험(15p)
- 신규 사용자에게 5개의 할 일이 동시에 제시되면 "어디부터 시작하지?" 혼란
- "나무 물주기"와 "페르소나 탐험"은 핵심 가치와 거리가 있어 주의 분산

**영향 범위**
- `components/onboarding/onboarding-checklist.tsx` - 5개 아이템 정의
- `components/dashboard/sections/home-hero-section.tsx` - 체크리스트 렌더링 위치

**행동경제학적 분석**
- Endowed Progress Effect를 의도했으나 (시작부터 일부 완료), 5개 항목은 Goal Gradient Effect 약화
- 2~3개로 단순화하면 완료율 향상 예상 (Zeigarnik Effect 활용)

### 4.5 Retention Gap: 활동 없는 Tertiary Zone이 null로 숨겨짐

**현상**
- `tertiary-zone-client.tsx`에서 `!hasActivityData && !hasPersonaData`일 때 `return null` 처리
- 신규 사용자 또는 활동이 적은 사용자에게 Tertiary Zone(월간 캘린더, 페르소나 인사이트) 전체가 사라짐
- 격려 메시지나 대안 콘텐츠 없이 빈 공간만 남음

**영향 범위**
- `components/dashboard/tertiary-zone-client.tsx` - 조건부 null 반환 (130-132줄)
- `components/dashboard/sections/home-hero-section.tsx` - PersonaInsightCard null 반환 (530줄)

**기회**
- 빈 Tertiary Zone을 "데이터가 쌓이면 여기에 나타날 것들" 미리보기로 전환
- 월간 캘린더 빈 상태에서 "이번 달 첫 기록을 남겨보세요" 격려 메시지

## 5. 종합 진단

### 5.1 강점 (Strengths)
- 기술적으로 성숙한 아키텍처 (RLS, 서버 액션 분리, 타입 안전성)
- 게이미피케이션 요소가 잘 설계됨 (나무, 포인트, 스트릭)
- 게스트 모드로 가입 전 가치 체험 가능
- 감정적 디자인 기반 인프라 (EmptyState 변형 시스템)

### 5.2 약점 (Weaknesses)
- Cold Start 구간의 전환 마찰이 높음
- 인기 도서/추천 등 콘텐츠 발견(Discovery) 기능 부재
- 빈 상태 처리가 기능적 수준에 머물러 있음 (감정적 설계 미활용)
- 온보딩의 인지부하가 높음

### 5.3 기회 (Opportunities)
- `not_started` 상태를 "위시리스트"로 리포지셔닝하면 Cold Start 크게 완화
- EmptyState 변형을 적극 활용하면 코드 변경 최소화로 UX 개선 가능
- 기존 사용자 데이터 기반 인기 도서 기능 구현 가능
- 온보딩 체크리스트 단순화로 완료율 향상 가능

### 5.4 위협 (Threats)
- Cold Start 미해결 시 가입-첫 행동 전환율 저하
- 빈 상태 경험이 부정적이면 초기 이탈 증가
- 독서 앱 시장 경쟁 심화 (밀리의서재, 리디, 북적북적 등)
