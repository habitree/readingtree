✅ 최종 결정 (2026-04-20, 재검토 후 Supabase 채택) 안정성 Wave 4

Rate Limit: Supabase rate_limits 테이블 + RPC (Upstash Redis 철회)

"Redis가 꼭 필요한가?" 재검토 결과, 동일 Seoul region인 Supabase가 더 빠르고 간결. 비용 0.

✓ 최종 채택: Supabase 기반 — public.rate_limits 테이블 + rate_limit_check(token, limit, window) RPC. 원자적 UPSERT로 race 방지. Vercel Seoul → Supabase Seoul ~5-10ms(동일 region). fail-open(DB 장애 시 메모리 fallback). 추가 인프라·비용·환경변수 모두 0.
Upstash Redis Free + AWS Tokyo — region 열위(~30-40ms), 외부 인프라 관리 복잡도. 철회
메모리 유지 + Wave 5 연기 — 다중 인스턴스 정확도 70~90% 수준

  • RPC 동작 검증: 5회 허용 → 6회째 success:false, remaining:0 확인

  • Upstash 패키지 제거, .env.example에서 UPSTASH 변수 삭제
  • 타입체크 통과
