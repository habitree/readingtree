## 1. 프로젝트 핵심 기능 요약

### Tier 1 — 핵심 (매일 사용)
1. **독서 기록 시스템** — 책 등록, 상태 관리, 진행률 추적, 완독 회고
2. **노트 시스템** — 인용구/메모/사진/OCR필사/진행기록 5종 노트 생성·관리
3. **대시보드** — 독서나무 시각화, 연속 읽기, 주간 진행, 최근 기록

### Tier 2 — 보조 (주간 사용)
4. **서재 관리** — 커스텀 서재 생성, 분류, 공개 공유
5. **통계** — 월별/연별 독서 통계, 활동 히트맵, 독서 지표
6. **포인트/게이미피케이션** — 28종 포인트 액션, 일일 미션, 스트릭, 레벨, 업적

### Tier 3 — 확장 (월간 사용)
7. **독서 그룹** — 그룹 독서, 멤버 관리, 노트 공유, 초대 링크
8. **AI 기능** — 채팅, 책 요약, OCR 필사, 자동 태깅, 독서 페르소나 분석
9. **커뮤니티** — 기능 요청, 투표, 댓글

## 3. UX 단순화 제안

### 3-1. 5초 핵심 가치 전달 실패 → 해결

**현재 문제**: 대시보드에 7개 섹션 동시 노출 → 핵심 가치 파악 어려움

```
현재 흐름:
홈 → [나무 Hero] [이어읽기] [주간바] [최근책] [최근노트] [캘린더] [월간요약]
        ↑ 무엇을 해야 할지 불명확

개선 흐름:
홈 → [오늘의 할 일 1개] → [이어읽기 CTA] → [나머지는 스크롤]
        ↑ 즉시 행동 유도
```

**구체적 개선:**

| # | 현재 | 개선 | 기대 효과 |
|---|------|------|----------|
| 1 | Hero에 나무+스트릭+페르소나+포인트 동시 표시 | **"오늘 할 것"** 1가지만 Hero에 배치 (이어읽기 or 미션) | 전환율 2-3배 |
| 2 | 7개 섹션 동시 로드 | 접힌 섹션으로 변경, 상위 3개만 펼침 | 초기 로드 40% 감소 |
| 3 | 게스트 배너가 작은 알림 형태 | 풀폭 CTA with 샘플 데이터 미리보기 | 가입 전환율 향상 |

### 3-2. 불필요한 클릭 수 단축

| 흐름 | 현재 클릭 | 개선 클릭 | 방법 |
|------|----------|----------|------|
| 노트 작성 | 3+ (FAB → 타입 선택 → 책 선택 → 작성) | 1 (FAB → 바로 입력창) | 타입 자동 감지, 책은 "이어읽기" 자동 선택 |
| 진행률 업데이트 | 3 (라이브러리 → 책 상세 → 페이지 입력) | 1 (홈 이어읽기 카드에서 직접 입력) | 인라인 페이지 입력 |
| 책 등록 | 2 (라이브러리 → 검색 → 추가) | 1 (홈 "+" 버튼 → 검색 시트) | 플로팅 추가 버튼 |
| 그룹 가입 | 3+ (메뉴 → 그룹 → 검색 → 가입) | 1 (초대 링크 클릭) | 초대 링크 강화 |

### 3-3. 핵심 CTA 재배치

```
모바일 하단 네비 (현재):
[홈] [서재] [+노트] [타임라인] [더보기]

모바일 하단 네비 (개선):
[홈] [서재] [+기록] [통계] [더보기]
                ↑ FAB에 "노트"뿐 아닌 "진행률 업데이트"도 포함
```

**사이드바 재배치:**
```
Primary (현재): 홈, 라이브러리, 검색, 타임라인, 프로필
Primary (개선): 홈, 라이브러리, 기록하기, 그룹, 프로필
                              ↑ 검색은 헤더로, 타임라인은 More로
```

### 3-4. 시각적 계층 개선

| 요소 | 현재 | 개선 |
|------|------|------|
| 독서 상태 배지 | 텍스트 배지 | 컬러 코딩 + 아이콘 (읽는중=파랑, 완독=초록, 일시정지=회색) |
| 진행률 | 숫자(%) | 원형 프로그레스 바 + 숫자 |
| 스트릭 | 숫자만 | 불꽃 아이콘 + 연속일수 + "최고 기록 대비 N일" |
| 포인트 | 숫자 | 레벨 배지 + 다음 레벨까지 진행바 |

## 4. CTO 기술 강화 리뷰

### 4-1. 아키텍처

**현재**: 모놀리식 Next.js 앱 (server actions 패턴)

| 항목 | 현재 상태 | 문제 | 개선안 | 난이도 |
|------|----------|------|--------|--------|
| **기능 분리** | `groups.ts` 2,814줄, `books.ts` 2,160줄 | 단일 파일 과대 → 유지보수 난이도 증가 | 도메인별 모듈 분리: `actions/groups/` 폴더 → `members.ts`, `books.ts`, `sharing.ts` 분리 | 중 |
| **API 구조** | 14개 API route + 150+ server action 혼재 | Server action과 API route 역할 구분 불명확 | AI/OCR/외부연동만 API route, 나머지는 server action으로 통일 | 하 |
| **캐싱 전략** | React `cache()` 3곳, `revalidatePath` 광범위 사용 | `unstable_cache()` 미사용 → 요청 간 캐시 공유 없음 | 대시보드 데이터에 `unstable_cache()` 60초 TTL 적용 | 중 |
| **클라이언트 캐시** | `lib/utils/cache.ts` 커스텀 구현 | 5분 interval 클린업, 무효화 알림 없음 | SWR/React Query 도입 또는 캐시 무효화 이벤트 추가 | 중 |

| **커스텀 캐시 vs SWR** | `lib/utils/cache.ts` 자체 구현 | 🟡 중간 | 표준 라이브러리 채택 검토 |
| **CustomEvent 남용** | `use-navigation-state.ts` DOM 이벤트 dispatch | 🟢 낮음 | zustand subscribe 패턴으로 전환 |

## 결론

Habitree는 **기능적으로 매우 풍부한** 상태 (47 라우트, 150+ 서버 액션, 31 테이블) 이지만, 프리런칭 단계에서 가장 중요한 것은 **"기능을 더 만드는 것"이 아니라 "기존 기능을 더 강하게 만드는 것"** 입니다.

**즉시 실행할 3가지:**
1. 🎯 **대시보드 단순화** — 5초 안에 "오늘 할 일"이 보여야 한다
2. ⚡ **노트 작성 원탭화** — 가장 자주 하는 행동이 가장 쉬워야 한다
3. 🔗 **완독 공유 카드** — 매 완독이 새로운 사용자를 데려와야 한다

기술 기반은 탄탄합니다. 인증, RLS, 미들웨어, 레이어 분리 모두 올바른 패턴을 따르고 있습니다. 성능 최적화 (memo, 낙관적 업데이트)와 코드 품질 (대형 파일 분리, 테스트) 개선을 런칭과 병행하면 안정적인 성장 기반을 갖출 수 있습니다.
