> 목적: 기록 기획 13(①②④ 통합 피드/뷰/책상세 + ③ 진행율 reading_logs 단일화)을 프로덕션에 배포·백필한 뒤, **로그인 상태에서만 확인 가능한 UI**를 사람/에이전트가 육안·자동으로 검증한다. (이 부분은 헤드리스 도구로 검증 불가였음)

## 0. 배경 (지금까지 적용된 것)

- **프로덕션 URL:** `https://readingtree-tan.vercel.app`
- **배포 커밋:** `3b0040d` (Vercel 프로덕션 READY)
- **활성 플래그(둘 다 ON):**
  - `NEXT_PUBLIC_UNIFIED_FEED=ON` → 통합 기록 피드(①②④)
  - `NEXT_PUBLIC_PROGRESS_IN_LOGS=ON` → 진행율 기록이 `reading_logs`로 저장(③)
- **백필 완료:** 기존 진행 기록 `notes(type='progress')` **196건 → `reading_logs` 196건** 이관(손실·중복·고아 0, 메모 31건·시각 보존). 이관 후 `notes`의 progress는 0건.
- **검증된 것:** 데이터 무결성, 빌드/배포 健全성, 게스트 페이지 콘솔 에러 0.
- **미검증(=이 문서의 대상):** 로그인 후 여정·캘린더·스트릭·대시보드·통합 피드의 **실제 화면 표시**.

## 2. 검증 시나리오 (순서대로 실행)

### V1. 로그인
- **동작:** `/login` 이동 → 테스트 계정으로 로그인.
- **합격:** 로그인 성공, 상단에 "로그인" 링크가 사라지고 사용자 메뉴/아바타 노출.
- **실패 시:** 인증 문제 — 이후 V2~V9 진행 불가. 중단하고 보고.

### V2. 진행율 기록 생성 → reading_logs 반영 (③ 핵심)
- **경로:** 내 서재 → 진행 중인 책 1권 → 책 상세(`/books/[id]`)
- **동작 A (메모 없이):** "진행률" 슬라이더를 현재보다 **앞 페이지로** 드래그 → 인라인 입력에서 **"메모 없이 저장"**.
- **동작 B (메모 포함):** 다시 슬라이더 이동 → 메모 입력 → **"기록 저장"**.
- **합격:**
  - 토스트로 저장 성공.
  - 같은 책 상세의 **"기록" 탭**(통합 피드) 또는 **여정 탭**에 방금 진행이 **"진행" 카드/점**으로 즉시(새로고침 포함) 표시.
  - `/notes` 전체 피드 상단(오늘) 그룹에 **"진행" 배지** 카드로 표시.
- **실패 시:** 저장 실패 토스트 / 어디에도 안 보임 → ③ forward-write 또는 dual-source 문제. 메모(불합격 사유) 기록 후 계속.

### V3. /notes 통합 피드 — 표시·필터·뷰 (①④)
- **경로:** `/notes` (전체 탭, list 뷰)
- **합격 기준:**
  1. **그룹 헤더** "오늘/어제/날짜 · 책제목" 아래 카드들이 시간순으로 보임.
  2. 한 피드에 **시간세션·진행·스탬프·구절/메모/필사** 카드가 **섞여** 보임(각 카드에 작은 종류 배지).
  3. 상단 **종류 필터** `[전체][시간][진행][스탬프][상세]` 클릭 시 해당 종류만 필터됨. "진행" 선택 → 진행 카드만.
  4. 뷰 토글 **타임라인** → "YYYY년 M월" 월 그룹, **책별** → 책 제목 그룹으로 바뀜.
  5. 하단 **"더 보기"** 클릭 시 다음 페이지가 누락/중복 없이 append.
- **실패 시:** 어떤 항목이 깨졌는지 번호로 기록.

### V4. 책 상세 — "기록" 탭(통합 피드) + 여정 탭 (②③)
- **경로:** 진행 기록이 있던 책 상세
- **합격:**
  1. **"기록" 탭** = 그 책의 통합 피드(시간/진행/스탬프/상세). 종류 필터 동작.
  2. **"여정" 탭** = 회독별 시각화에 **과거 진행 기록(백필분 포함)** 이 점/미리보기로 표시(누락 없음).
  3. **"독서 시간" 탭** = 시간 세션 정상(기존대로).
- **실패 시:** 여정에서 과거 진행이 사라졌으면 ③ dual-source(여정) 문제 — 즉시 기록·보고(롤백 후보).

### V5. 캘린더 / 활동 (③ dual-source)
- **경로:** 대시보드/홈 또는 활동 캘린더가 있는 화면
- **합격:** 진행 기록을 한 날짜에 만든 경우 그 날짜에 **진행(amber) 표시/카운트**가 잡힘. 과거 진행 기록일자도 캘린더에 반영.
- **실패 시:** 진행이 캘린더에서 빠지면 `getDailyRecordsByType` dual-source 문제.

### V6. 홈 — 스트릭 · 최근 진행 (③ dual-source)
- **경로:** `/` (홈)
- **합격:**
  1. **스트릭**: 오늘 진행 기록(V2) 후 오늘이 "기록함"으로 잡혀 스트릭 유지/증가.
  2. **최근 진행 체크** 카드: 최근 진행 기록(백필분 포함)이 표시.
- **실패 시:** `getWeeklyProgress`/`getRecentProgressLogs` dual-source 문제.

### V7. 단일 편집 (요구 3)
- **경로:** `/notes` 또는 책 상세 기록 탭의 **시간세션 카드** 탭(클릭)
- **합격:** 동일한 **사진 추가/편집 시트**가 열려 페이지·메모·사진을 수정·추가 가능. 저장 후 같은 카드가 갱신.
- **실패 시:** 편집 시트 안 열림/저장 실패 기록.

### V8. 과거 데이터 정합 (백필 검증, 가장 중요)
- **합격:**
  1. 백필 전부터 있던 **과거 진행 기록 196건 맥락**이 여정/피드/캘린더에 그대로 보임(누락 0).
  2. **이중 표시 0**: 같은 진행이 두 번 나오지 않음.
- **실패 시:** 누락 또는 이중 표시 발견 시 **즉시 롤백 검토**(아래 4장).

### V9. 모바일 반응형 (선택)
- 위 V3·V4를 모바일 뷰포트(390px)에서 1회 — 필터/그룹/카드 레이아웃 깨짐 없음.

## 4. 실패 시 즉시 롤백 (Vercel 환경변수 + Redeploy)

| 증상 | 조치 |
|---|---|
| 여정·캘린더·스트릭에서 진행 기록 누락/이중표시 (③ 문제) | `NEXT_PUBLIC_PROGRESS_IN_LOGS=0` 설정 + **Redeploy** → 진행 쓰기·리더가 기존 notes 경로로 복귀. **단, 백필로 notes의 progress는 이미 삭제됨** → 과거 진행을 notes로 되돌리려면 logs→notes 역마이그 필요(데이터는 `reading_logs`에 보존). 우선 플래그 OFF로 신규 쓰기만 안정화 후 코드 수정 권장. |
| 통합 피드 자체가 깨짐 (①②④ 문제) | `NEXT_PUBLIC_UNIFIED_FEED=0` 설정 + **Redeploy** → `/notes`·책 상세가 기존 notes 화면으로 폴백(비파괴). |
| 둘 다 | 위 두 변수 모두 `=0` + Redeploy |

> 롤백 후, 실패 항목(V번호)·증상을 개발자에게 전달하면 코드 수정 후 재배포.

## 5. 참고 데이터 (검증 보조)

- 백필 직후 DB: `notes`의 progress **0건**, progress `reading_logs` **196건**, orphan 0, 메모 31건.
- "진행 기록" 식별: `reading_logs` 중 `reading_duration_seconds=0 AND image_url IS NULL AND end_page≠NULL`.
- 새 진행 기록도 같은 형태로 `reading_logs`에 쌓임(플래그 ON).
- 설계/구현 상세: `doc/update/기록기획/13-unified-record-feed.md`.
