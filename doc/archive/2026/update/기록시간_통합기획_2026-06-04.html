3.2 세 축의 관계 — 따로지만 이어진다

⏱ 독서시간 ──┐ ├──▶ 페이스 = pace_seconds_per_page = 시간 ÷ (읽은 페이지) → 예상 완독일 📊 진행률 ──┘ (시간 × 진행률의 결합) 📊 진행률(스냅샷) ──시간이 흐르며 값이 바뀜──▶ 🧭 여정(진행률의 시계열) └ 회독 완료(completed_dates)는 여정의 구간 경계
  • 독서시간 × 진행률 = 페이스. 둘을 곱하면(=나누면) "페이지당 N초", "이 속도면 며칠 후 완독"이 나온다. 이미 pace_seconds_per_page STORED 컬럼으로 계산되지만 UI 미노출(→ C2).
  • 진행률의 변화 이력 = 여정. 진행률은 "지금 어디"라는 한 점, 여정은 그 점들이 시간축에 쌓인 선. 즉 여정은 진행률의 시계열이다.
  • 회독 완료 = 여정의 구간 경계. completed_dates[]로 1회독·2회독을 분할(deriveReadingSessions).

4.1 기록시간 vs 독서시간 — 항목 정리 (혼동 해소)

"읽은 시각"과 "읽은 시간"은 다르다. 현재 대부분 UI가 앞의 것(기록시간)만 보여준다.

개념컬럼의미현재 표시
독서시간 (얼마나)reading_duration_seconds실제 읽은 길이(초)타이머 기록에만
독서 일시 (언제 읽음)started_at / ended_at독서 행위의 시각여정·일부
기록시간 (언제 적음)created_at기록을 남긴 시각거의 모든 UI
문제. 이어읽기 카드·진행로그·여정이 모두 created_at 기반 "~에 읽음"만 노출 → 사용자가 "오늘 23분 읽었다"는 핵심 정보를 보지 못함. 정리 방향: "읽은 시각(기록시간)"과 "읽은 시간(독서시간)"을 라벨로 분리하고, 내 기록 항목마다 독서시간 배지를 노출(→ C6).
