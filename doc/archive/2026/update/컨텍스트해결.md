# Claude Code 컨텍스트 오버플로우 해결 가이드

Claude Code는 **200K 토큰 컨텍스트 윈도우**를 사용합니다. Plan 모드에서 탐색·추론·도구 호출이 누적되면 컨텍스트가 가득 차서 진행이 멈추고, `/compact`조차 실패하는 상황이 발생할 수 있습니다.

이 문서는 프로젝트에 관계없이 적용 가능한 범용 해결책을 정리합니다.

---

## 1. 선제적 `/compact` 실행

가장 중요한 규칙입니다.

- 컨텍스트 사용량이 **~70%**에 도달하면 즉시 `/compact` 실행
- **100%까지 기다리면 compact 자체가 실패**하는 알려진 버그 존재
- 특정 주제에 집중하여 압축 가능: `/compact focus on the auth flow decisions`

> 100%에서 `/compact`가 "Conversation too long" 오류로 실패하는 것은 확인된 이슈입니다.
> [GitHub #26317](https://github.com/anthropics/claude-code/issues/26317)

---

## 2. `/compact` 실패 시 워크어라운드

100%에 도달하여 `/compact`가 실패했을 때 (GitHub에서 "100% 성공률" 보고된 방법):

```
1. Claude Code 완전 종료 (프로세스 종료)
2. claude --continue 으로 재시작
3. 아무 메시지도 보내기 전에 즉시 /compact 실행
```

**핵심**: 재시작 직후에는 새 시스템 프롬프트만 로드된 상태이므로 `/compact`가 동작합니다.

### `--continue` vs `--resume` 차이

| 옵션 | 동작 | 용도 |
|------|------|------|
| `--continue` | 가장 최근 세션을 이어서 시작 | compact 실패 복구, 작업 이어가기 |
| `--resume` | 특정 세션 ID를 지정하여 재개 | 과거 세션으로 돌아가기 |

```bash
# 최근 세션 이어가기
claude --continue

# 특정 세션 재개
claude --resume <session-id>
```

> `--continue`는 세션의 전체 대화 히스토리를 로드하므로, 컨텍스트가 이미 큰 세션을 이어가면 바로 높은 사용량에서 시작합니다. compact를 먼저 실행하세요.

## 3. Plan/Implementation 세션 분리

가장 근본적인 해결책입니다.

### Plan 세션
1. 코드베이스 탐색
2. 아키텍처 분석
3. 구현 계획 작성
4. **계획을 파일로 저장** (예: `.claude/plans/feature-xxx.md`)

### Implementation 세션
1. `/clear`로 컨텍스트 초기화 (또는 Plan 모드 종료 시 "Clear context and implement" 선택)
2. 저장된 계획 파일을 참조하며 구현
3. 계획 파일이 컨텍스트 역할을 하므로 재탐색 불필요

Plan 모드 종료 시 기본 선택이 "Clear context and implement"인 이유가 바로 이 패턴을 의도한 것입니다.

## 4. Subagent로 탐색 위임

코드베이스 탐색을 서브에이전트에 위임하면 **부모 컨텍스트를 보호**할 수 있습니다.

- `Task(subagent_type=Explore)` — 독립된 컨텍스트 윈도우에서 실행
- 결과만 요약으로 반환 → 부모 컨텍스트에 최소한의 토큰만 추가
- **최대 3개까지 병렬** 실행 가능

### 효과적인 활용 예시

```
직접 탐색: Grep → Read → Grep → Read ... (컨텍스트 급속 소비)
서브에이전트: Task(Explore) → 요약 결과 1개만 반환 (컨텍스트 절약)
```

특히 Plan 모드에서 여러 영역을 동시에 조사할 때 유효합니다.

## 5. Checkpoint 활용

Claude Code는 도구 호출마다 체크포인트를 생성합니다.

1. `/rewind`로 체크포인트 목록 확인
2. 특정 체크포인트에서 **"Summarize from here"** 선택
3. 선택 지점 이전의 대화만 압축, 이후 내용은 전체 해상도 유지

**효과**: 80~95% 토큰 절감 (5,000~15,000 토큰 → 500~1,500 토큰)

## 6. CLAUDE.md / MEMORY.md / .agent/rules 최적화

이 파일들은 **매 세션마다 자동 로드**되므로 크기가 곧 기본 컨텍스트 소비량입니다.

### 권장 구조
```
CLAUDE.md           ← 핵심 규칙만 (~100줄 이하)
MEMORY.md           ← 핵심 요약 + 상세 파일 링크 (~100줄 이하)
memory/topic-a.md   ← 상세 내용 (필요 시 Read로 로드)
memory/topic-b.md
```

### .agent/rules alwaysApply 관리

`.agent/rules/` 파일의 `alwaysApply: true`는 **매 세션에 무조건 로드**됩니다. 대부분의 규칙은 `alwaysApply: false` + `globs` 패턴으로 조건부 로드하세요.

```yaml
# 좋은 예: 조건부 로드
---
alwaysApply: false
description: "마이그레이션 파일 작성 시 적용하는 규칙"
globs:
  - "doc/database/migration-*"
---

# 나쁜 예: 항상 로드 (494줄 × 매 세션)
---
alwaysApply: true
---
```

**alwaysApply: true 기준**:
- 13줄 이하의 기본 규칙만 alwaysApply 유지
- 100줄 이상의 규칙은 반드시 globs 조건부로 전환
- `description` 필드를 추가하여 규칙의 용도를 명시

### 주의사항
- CLAUDE.md에 로드맵, 변경 이력 등 장문 내용을 넣지 말 것
- CLAUDE.md에서 다른 파일의 강제 Read 지시를 넣지 말 것 (이중 로드 위험)
- 프로젝트 컨벤션·패턴은 CLAUDE.md에, 상세 가이드는 별도 파일로 분리
- MEMORY.md는 200줄 이후 자동 truncate됨

## 7. 작업 범위 제한

### 1세션 = 1태스크 원칙

| Bad | Good |
|-----|------|
| 1세션에서 기능 구현 + 디버깅 + 리팩토링 | 태스크별 세션 분리 |
| 50개 파일 일괄 수정을 한 세션에서 | 10개씩 나누어 5세션 |
| Plan + Implement 연속 진행 | Plan 저장 → `/clear` → Implement |

### 세션 종료 시그널
- 컨텍스트 70% 이상
- 태스크 하나 완료
- 방향이 크게 바뀌었을 때

태스크 완료 후 `/clear`로 깨끗하게 시작하세요.

## 8. `.agent/rules` 관리 전략

### alwaysApply 감사 체크리스트

정기적으로 (월 1회 또는 규칙 추가 시) `.agent/rules/` 파일을 감사하세요.

```bash
# 현재 alwaysApply 상태 확인
grep -l "alwaysApply: true" .agent/rules/*.md
```

| 확인 항목 | 기준 |
|-----------|------|
| alwaysApply: true인 파일 수 | 1~2개 이하 |
| alwaysApply: true 파일의 총 줄 수 | 50줄 이하 |
| globs 패턴이 없는 false 파일 | 0개 (반드시 globs 설정) |
| description이 없는 파일 | 0개 (반드시 설명 추가) |

### globs 패턴 설계 원칙

1. **최소 매칭**: 규칙이 필요한 파일만 정확히 매칭
2. **중복 방지**: 여러 규칙이 같은 파일에 매칭되면 토큰 낭비
3. **테스트**: 새 globs 추가 후 해당 파일 수정 요청으로 규칙 로드 확인

```yaml
# 좋은 예: 구체적 패턴
globs: ["doc/database/migration-*"]

# 나쁜 예: 너무 넓은 패턴
globs: ["**/*"]
```

### ReadTree 현재 규칙 매핑

| 규칙 파일 | alwaysApply | globs | 줄 수 |
|-----------|-------------|-------|-------|
| `rdrule.md` | true | - | 13 |
| `migration_rule.md` | false | `doc/database/migration-*` | 494 |
| `db_rls_rule.md` | false | `doc/database/**`, `types/database.ts` | 477 |
| `ui_datarule.md` | false | `components/**`, `hooks/**`, `app/actions/**` | 382 |
| `auth_session_rule.md` | false | `app/actions/auth.ts`, `contexts/auth-context.tsx`, `lib/supabase/**` | 324 |
| `datarule_2.md` | false | `app/actions/**`, `hooks/**` | 150 |
| `datarule_1.md` | false | `doc/database/DATA_MODEL.md`, `types/database.ts` | 128 |
| `mobile_performance_rule.md` | - | - | (frontmatter 없음) |
| `component_pattern_rule.md` | - | - | (frontmatter 없음) |
| `code_review_checklist.md` | - | - | (frontmatter 없음) |

## 9. Plan 파일 저장 컨벤션

### 저장 위치 구분

| 위치 | 용도 | 특징 |
|------|------|------|
| `.claude/plans/` | Claude Code Plan 모드 출력 | gitignore 대상, 임시 |
| `doc/plan/` | 프로젝트 영구 계획서 | git 관리, 팀 공유 |

### 네이밍 규칙

```
.claude/plans/
├── 2026-02-19-context-overflow-fix.md   ← 날짜-기능
└── 2026-02-20-auth-refactor.md

doc/plan/
├── 페르소나-기반-확장기능-기획문서.md    ← 한국어 OK
└── v4.1-roadmap.md
```

### Plan → Implementation 워크플로우

```
1. Plan 모드 진입
2. 탐색 및 분석
3. 계획을 .claude/plans/YYYY-MM-DD-feature.md에 저장
4. Plan 모드 종료 → "Clear context and implement" 선택
5. 새 세션에서 계획 파일 참조하며 구현
```

## 10. 세션 시작/종료 체크리스트

### 세션 시작 시

- [ ] 이전 세션의 미완료 작업 확인 (`memory/MEMORY.md` 참조)
- [ ] 현재 작업에 필요한 규칙만 로드되는지 확인
- [ ] 대규모 작업이면 Plan 모드로 시작

### 세션 중

- [ ] 컨텍스트 70% 접근 시 `/compact` 실행
- [ ] 코드 탐색이 길어지면 Explore 서브에이전트로 위임
- [ ] 중간 결과물은 파일로 저장 (컨텍스트 소실 대비)

### 세션 종료 시

- [ ] 주요 결과를 `memory/MEMORY.md`에 기록
- [ ] 상세 내용은 `memory/topic-xxx.md`로 분리
- [ ] 미완료 작업은 다음 세션을 위해 계획 파일로 저장
- [ ] git commit (필요 시)

## 빠른 참조 표

| 상황 | 행동 |
|------|------|
| 컨텍스트 70% 도달 | 즉시 `/compact` |
| `/compact` 실패 (100%) | 종료 → `claude --continue` → `/compact` |
| Plan 모드에서 대규모 탐색 | Explore 서브에이전트로 위임 |
| Plan 완료 후 구현 시작 | "Clear context and implement" 선택 |
| 다영역 스프린트 | 영역별로 세션 분리 |
| 대규모 리팩토링 | Plan을 파일로 저장 → 새 세션에서 구현 |
| 긴 대화 중 중간 정리 | `/rewind` → "Summarize from here" |
| `.agent/rules` 감사 | `grep "alwaysApply: true"` → 50줄 이하 유지 |
| 규칙 추가 시 | alwaysApply: false + globs 설정 기본 |
