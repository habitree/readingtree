# 포인트·차감·출석·리더보드 고도화 계획안

**문서 성격**: 적용 전 검토·고도화용 계획안 (바로 적용하지 않으며, 추가 업데이트 예정)  
**관련 문서**: [doc/ReadTree-PRD.md](ReadTree-PRD.md), [types/points.ts](../../types/points.ts), [app/actions/points.ts](../../app/actions/points.ts)  
**최종 수정**: 2026-02

---

## 1. 목적 및 범위

### 1.1 목적

- 기록·수정·개선안 등록/반영에 대한 포인트 부여로 참여 동기 강화
- 매일 출석형 포인트로 재방문 유도
- GPT/OCR 등 AI 사용에 따른 포인트 차감으로 비용과 이용의 균형 유지
- 기록·서재 데이터가 많을수록 일부 기능 무상 지원으로 "더 쌓고 싶다"는 동기 부여
- 리더보드 도입으로 포인트에 대한 욕구와 성취감 제공

### 1.2 범위

- **포인트 적립 확장**: 기록 등록·수정·개선사항 등록·개선 반영 시 포인트
- **출석 포인트**: 매일 출석 형태의 포인트 증가
- **포인트 차감**: GPT 사용 토큰·OCR/AI 사용에 따른 차감
- **무상 한도**: 기록/서재 데이터량에 따른 특정 기능 무상 지원
- **심리 설계**: 데이터가 많을수록 구분을 두어 입력·서재 축적 동기 강화
- **리더보드**: 포인트 기준 순위(추후 추가)

### 1.3 비범위 (현재 단계)

- 실제 코드 반영 시점·스프린트는 별도 결정
- 포인트 구매·현금화·유료 결제 연동은 본 계획안 범위 외

---

## 2. 현행 시스템 요약

- **적립만 존재**: `earnPoints()`, `point_transactions`에 양수만 적재
- **잔액**: `user_points.total_points`(현재 보유), `lifetime_points`(레벨용 누적, 감소 없음)
- **출석/스트릭**: `daily_first_activity`, `streak_7/30/100_days` 등
- **차감·GPT·OCR**: 미구현
- **리더보드**: 랭킹 조회용 로직만 존재, UI/운영 정책 미정

---

## 3. 상세 계획

### 3.1 포인트 적립 확장

| 구분 | 설명 | 비고 |
|------|------|------|
| 기록 등록 | 기존 노트 타입별 포인트 유지·정비 | `note_create`, `note_quote`, `note_memo` 등 |
| 기록 수정 | 수정 시 소량 포인트 (예: 신규의 50%) | 스팸 방지용 일일 한도 검토 |
| 개선사항 등록 | 제안 1건당 포인트 | 새 액션 타입 `improvement_suggest` |
| 개선 반영 | 운영자가 반영 처리 시 제안자에게 추가 포인트 | 새 액션 타입 `improvement_applied` |

- 새 액션은 `PointActionType` 및 `point_action_configs`에 추가
- 반영 시 포인트는 서버(관리자 액션)에서 `earnPoints("improvement_applied", { referenceId })` 호출

### 3.2 매일 출석 포인트

- 현행 `daily_first_activity`를 "출석" 개념으로 활용 또는 "출석 체크인" 전용 액션 1종 추가
- 일일 1회 제한(`daily_limit`) 유지
- (선택) 출석 연속 일수에 따른 추가 보상 구간 검토

### 3.3 포인트 차감 (GPT/OCR·AI)

| 항목 | 방향 |
|------|------|
| GPT 사용 | 토큰 수(또는 요청 단위)에 비례해 포인트 차감 |
| OCR/AI 적용 | 이미지 수·요청 수 등에 비례해 포인트 차감 |
| 차감 시점 | 서버(API/Server Action)에서 사용량 기록 후 `deductPoints()` 또는 `point_transactions` 음수 삽입 |
| 거래 타입 | `gpt_usage`, `ocr_usage` 등 차감 전용 액션 타입 정의 |
| 메타데이터 | `tokens`, `images`, `unit_cost` 등 저장해 정책 변경 대비 |

- `total_points`는 0 미만 불가 제약
- `lifetime_points`는 차감 시에도 변경 없음(레벨·리더보드 기준)

### 3.4 무상 한도 (기록량·서재량 기반)

- **기준**: 사용자별 기록 수(notes), 서재 책 수(user_books) 등
- **규칙 예시**:
  - 기록 N개 미만: OCR/AI 1일 M회까지 포인트 차감
  - 기록 N개 이상: OCR 1일 K회 무상, 초과분만 차감
  - 서재 P권 이상: AI 요약 1일 Q회 무상 등
- **구현**: 차감 전 "이번 호출이 무상인지" 판단하는 `getUsageAllowance(userId, feature)` 또는 면제 규칙 테이블
- **노출**: "기록 O개 더 쌓으면 이 기능 무상" 등 다음 목표 문구로 신규 이탈 완화

### 3.5 심리·동기 설계

- **데이터가 많을수록 구분**: 티어/배지(기록 50개, 서재 30권 등)와 무상 한도 구간 연동
- **내재 동기 유지**: 포인트보다 "기록이 쌓일수록 받는 혜택"을 전면에 노출
- **공정성**: 신규에게 "앞으로 N개 더 쌓으면 무상" 같은 목표 제공
- **리더보드**: 자기 구간·비슷한 레벨 비교 위주, 상위만 노출 또는 이벤트성 1등 강조

### 3.6 리더보드 (추후)

- **기준**: `lifetime_points` (총 누적 획득량)
- **옵션**: 주간/월간 리셋 시 `leaderboard_snapshots` 등 스냅샷 테이블로 부하 분산
- **노출**: "내 순위 + 주변 구간" 위주로 설계해 이탈 완화

## 4. 기술·데이터 관점

### 4.1 차감 거래

- `point_transactions`에 `final_points` 음수 허용, `balance_after` 매 거래 저장
- 차감 전 `total_points >= 필요 포인트` 검사 후 원자적으로 차감·거래 삽입

### 4.2 무상 한도

- 기록 수/서재 수는 기존 테이블 집계 또는 캐시로 조회
- 기능별 "일일 무상 횟수" + "일일 최대 사용 횟수(무상+유료)" 상한 권장

### 4.3 남용 방지

- GPT/OCR 호출당 일일 상한(회수·포인트 상한) 검토
- 개선안·수정 포인트는 일일 한도로 스팸 억제

## 5. 단계별 도입 (안)

| 단계 | 내용 |
|------|------|
| 1 | 기록·수정·개선안·개선 반영 포인트 액션 추가, 출석 포인트 정비 |
| 2 | GPT/OCR 사용량 로깅 및 포인트 차감, 기록/서재 기반 무상 한도 규칙 정의 및 적용 |
| 3 | 리더보드 UI 및 (선택) 주간/월간 스냅샷 |
| 4 | 티어별 무상 한도 세분화, 포인트량·차감량 A/B 테스트 및 튜닝 |

## 6. PRD·지표와의 정렬

- **재방문율**: 출석 포인트
- **기록 재사용률**: "기록이 많을수록 AI 무상"으로 재사용 동기
- **기록량·참여**: 기록/수정/개선안 포인트
- 리더보드는 참여·체류 보조, "기록 재사용"은 무상 한도·혜택 메시지로 연결
