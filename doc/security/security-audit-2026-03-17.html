C2

포인트 차감 Race Condition (TOCTOU 취약점)

위치: app/actions/points.ts:759-835 — spendPoints()

CWE: CWE-367 (Time-of-Check-Time-of-Use)

문제: 잔액 확인과 차감이 비원자적(non-atomic)으로 수행됩니다. 동시 요청 시 이중 차감 또는 음수 잔액이 발생합니다.

// 1단계: 잔액 확인 (라인 780)
const userPoints = await getUserPoints(currentUser);
if (userPoints.total_points < cost) return fail;

// ❌ 여기서 다른 요청이 개입 가능 (Race Window)

// 2단계: 트랜잭션 삽입 (라인 799)
await supabase.from("point_transactions").insert({...});

// 3단계: 잔액 업데이트 (라인 819) — 이미 stale 값
await supabase.from("user_points")
  .update({ total_points: newTotal })  // ← TOCTOU

공격 시나리오: 사용자가 40P 보유, AI Chat 비용 40P → 동시 2개 요청 → 둘 다 잔액 확인 통과 → 80P 차감 → 잔액 -40P

권장 조치: DB 레벨 원자적 RPC 함수 생성
CREATE OR REPLACE FUNCTION spend_points_atomic(
  p_user_id UUID, p_action TEXT, p_cost INT
) RETURNS JSONB AS $$
DECLARE v_row RECORD;
BEGIN
  SELECT * INTO v_row FROM user_points
  WHERE user_id = p_user_id FOR UPDATE;  -- 행 잠금

  IF v_row.total_points < p_cost THEN
    RETURN '{"success":false}'::jsonb;
  END IF;

  UPDATE user_points SET total_points = total_points - p_cost
  WHERE user_id = p_user_id;
  -- ... 트랜잭션 기록 삽입 ...
  RETURN jsonb_build_object('success', true);
END; $$ LANGUAGE plpgsql SECURITY DEFINER;

if (!access.allowed && access.canUseWithPoints) {
