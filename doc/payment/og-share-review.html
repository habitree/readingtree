2. 발견 및 수정된 문제

FIXED — 독서 기록 / 서재 OG 이미지 500 에러

원인: Satori (Next.js OG 이미지 렌더러)는 모든 <div>가 자식 노드 1개 이하이거나, display: flex를 명시해야 합니다.
JSX에서 {변수}한글텍스트 패턴은 React가 2개의 별도 텍스트 노드로 분리하여 Satori가 "다중 자식" 에러를 발생시켰습니다.

// Before (2개 자식 노드 = Satori 에러)
<div>{displayName}님의 독서기록</div>
<div>p.{note.page_number}</div>

// After (1개 자식 노드 = 정상)
<div>{`${displayName}님의 독서기록`}</div>
<div>{`p.${note.page_number}`}</div>

영향 범위: notes/opengraph-image.tsx (2곳), bookshelves/opengraph-image.tsx (1곳)

4-2. 카카오 공유 시 OG 이미지 적용 방식

카카오톡 공유에는 2가지 경로가 있습니다:

경로 이미지 소스 설명
Share API 직접 공유 content.imageUrl 코드에서 명시적으로 전달한 이미지 URL
카카오 서버가 이 URL을 직접 fetch하여 미리보기 생성
링크 붙여넣기 HTML <meta og:image> 사용자가 카카오톡 채팅에 URL을 붙여넣으면
카카오 크롤러가 HTML의 OG 메타 태그를 파싱

핵심: 두 경로 모두 OG 이미지 URL이 유효한 이미지를 반환해야 합니다.
500 에러가 발생하면 카카오톡에서 미리보기 이미지가 표시되지 않습니다.

Satori 필수 규칙 (위반 시 500 에러)

  • 자식이 2개 이상인 <div>는 반드시 display: "flex" 필요
    텍스트 노드도 자식으로 카운트됨! {변수}텍스트 = 2개 자식
  • CSS Flexbox만 지원 (Grid 불가)
  • 외부 이미지는 base64 data URI로 사전 변환 권장
  • 한글 폰트는 명시적 로드 필요 (NotoSansKR-SemiBold.otf)
  • position: absolute는 부모가 flex여야 작동

폰트 로드 전략

// 1차: 로컬 폰트 파일 (빌드 시 포함)
fetch(new URL("../../../../public/fonts/NotoSansKR-SemiBold.otf", import.meta.url))

// 2차: GitHub raw URL (폴백)
fetch("https://github.com/google/fonts/raw/main/ofl/notosanskr/NotoSansKR-SemiBold.otf")

// 3차: 폰트 없이 렌더링 (한글 깨질 수 있음)
