토스페이먼츠 결제 연동 체크리스트

DB 마이그레이션 이후 진행해야 하는 모든 설정 및 확인 사항

전체 진행 순서
1. DB 마이그레이션 → 2. 환경변수 설정 → 3. point_action_configs 데이터 → 4. 로컬 테스트 → 5. Vercel 배포 → 6. 웹훅 등록 → 7. 운영 전환

1 DB 마이그레이션 (Supabase SQL Editor)

중요: 2단계로 나눠서 실행해야 합니다!

ALTER TYPE ADD VALUE는 PostgreSQL에서 트랜잭션 블록 안에서 실행할 수 없습니다.

1단계: ENUM 확장 (먼저 단독 실행)

-- 이 부분만 복사해서 먼저 실행!
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_enum
    WHERE enumlabel = 'point_purchase'
    AND enumtypid = (SELECT oid FROM pg_type WHERE typname = 'point_action_type')
  ) THEN
    ALTER TYPE point_action_type ADD VALUE 'point_purchase';
  END IF;
END $$;
실행 후 확인 쿼리: 
SELECT enumlabel FROM pg_enum
WHERE enumtypid = (SELECT oid FROM pg_type WHERE typname = 'point_action_type')
ORDER BY enumsortorder;

결과에 point_purchase가 포함되어 있으면 성공!

2단계: 테이블 + RLS 생성 (ENUM 성공 후 실행)

마이그레이션 파일의 "2단계" 이후 전체를 복사해서 실행:

-- doc/database/migration-202603051200__payment__create_tables.sql
-- "2단계: 테이블 생성" 주석 아래부터 끝까지 실행
테이블 생성 확인 쿼리: 
SELECT table_name FROM information_schema.tables
WHERE table_schema = 'public'
AND table_name IN ('payment_orders', 'payment_history');

2 환경변수 설정 필수

토스페이먼츠 키 발급

  1. 토스페이먼츠 개발자센터 가입
  2. 상점 등록 (테스트 모드는 사업자 없이도 가능)
  3. 개발 정보 > API 키에서 테스트 키 확인

로컬 개발 환경 (.env.local)

# 토스페이먼츠 (테스트 키)
NEXT_PUBLIC_TOSS_CLIENT_KEY=test_ck_xxxxxxxxxxxx
TOSS_SECRET_KEY=test_sk_xxxxxxxxxxxx
변수명용도위치
NEXT_PUBLIC_TOSS_CLIENT_KEY 결제창 SDK 초기화 (브라우저) 클라이언트 + 서버
TOSS_SECRET_KEY 결제 승인 API 인증 (서버 전용) 서버 전용 (절대 클라이언트 노출 금지)

3 point_action_configs 데이터 추가 필수

이 단계를 빠뜨리면 결제 후 포인트 충전 시 point_purchase 액션이 동작하지 않을 수 있습니다. 
-- point_action_configs에 point_purchase 설정 추가
INSERT INTO point_action_configs (action_type, base_points, description, category, is_repeatable, daily_limit, is_active)
VALUES ('point_purchase', 0, '포인트 충전', 'system', true, null, true)
ON CONFLICT (action_type) DO NOTHING;
참고: point_purchase의 base_points는 0입니다. 실제 충전 포인트는 패키지별 금액에 따라 코드에서 계산되며, point_transactions에 직접 기록됩니다. earnPoints() 함수를 거치지 않고 confirm API에서 직접 처리합니다.

4 로컬 테스트 테스트

테스트 카드 정보

항목값
카드 번호4330-0000-0000-0014
유효 기간12/25
CVC123
비밀번호 앞 2자리00

테스트 시나리오 체크리스트

  • 정상 결제: /pricing에서 패키지 선택 → 결제 완료 → 포인트 충전 확인
  • 미로그인 리다이렉트: 로그아웃 후 충전 버튼 → /login 이동
  • 결제 취소: 결제창에서 X 닫기 → 에러 없이 원래 페이지 유지
  • 첫 충전 보너스: 첫 결제 시 2배 포인트 확인
  • 재충전: 두 번째 결제에서는 보너스만 (첫 충전 보너스 없음)
  • 포인트 잔액: 프로필/대시보드에서 충전 포인트 반영 확인

DB 데이터 검증 쿼리

-- 주문 확인
SELECT order_id, package_id, amount, points, bonus_points,
       first_purchase_bonus, status, payment_method, confirmed_at
FROM payment_orders
WHERE user_id = '사용자UUID'
ORDER BY created_at DESC;

-- 포인트 트랜잭션 확인
SELECT action_type, points, final_points, description, balance_after
FROM point_transactions
WHERE user_id = '사용자UUID' AND action_type = 'point_purchase'
ORDER BY created_at DESC;

-- 감사 로그 확인
SELECT event_type, payload, created_at
FROM payment_history
WHERE user_id = '사용자UUID'
ORDER BY created_at DESC;

-- 현재 포인트 잔액
SELECT total_points, lifetime_points
FROM user_points
WHERE user_id = '사용자UUID';

6 웹훅 URL 등록 가상계좌 사용 시 필수

등록 위치

토스페이먼츠 개발자센터 → 내 상점 → 웹훅 설정

항목값
URLhttps://your-domain.com/api/payment/webhook
이벤트DEPOSIT_CALLBACK, PAYMENT_STATUS_CHANGED
웹훅이 필요한 경우:
  • 가상계좌: 사용자가 입금하면 토스가 웹훅으로 알려줌 → 포인트 자동 충전
  • 결제 취소: 토스 대시보드에서 결제 취소 시 → 포인트 자동 회수

카드/간편결제만 사용한다면 웹훅 없이도 동작합니다 (confirm API에서 즉시 처리).

7 운영 전환 체크리스트

  • 토스페이먼츠에서 운영 키 발급 완료
  • Vercel Production 환경변수를 운영 키로 교체
  • 웹훅 URL을 운영 도메인으로 등록
  • 실제 카드로 최소 금액(₩1,900) 테스트 결제
  • 포인트 정상 충전 확인
  • 토스 대시보드에서 결제 취소 → 포인트 회수 확인
  • payment_orders, payment_history, point_transactions 데이터 정합성 확인
  • 운영 테스트 결제건 환불 처리

참고: 결제 흐름 상세

사용자 → "충전하기" 클릭
       ↓
[PricingPackageCard] → useTossPayment() 훅 호출
       ↓
[createPaymentOrder()] → Supabase에 pending 주문 생성
       ↓                   (첫 충전 여부 판단, 보너스 계산)
[loadTossPayments()] → 토스 SDK 초기화
       ↓
[payment.requestPayment()] → 토스 결제창 오픈
       ↓                      (카드/간편결제/계좌이체/가상계좌/휴대폰)
사용자 결제 완료 → 리다이렉트
       ↓
[/payment/success] → ?paymentKey=&orderId=&amount=
       ↓
[POST /api/payment/confirm]
  ├─ 1. Rate Limit 체크 (분당 10회)
  ├─ 2. 인증 확인 (supabase.auth.getUser)
  ├─ 3. DB 주문 조회 + 상태 확인
  ├─ 4. 금액 위변조 검증 (DB amount vs 전달 amount)
  ├─ 5. 토스 결제 승인 API 호출
  ├─ 6. payment_orders → confirmed 업데이트
  ├─ 7. user_points 포인트 충전
  ├─ 8. point_transactions 기록
  └─ 9. payment_history 감사 로그
       ↓
성공 화면: 충전 포인트 + 보너스 + 새 잔액 표시 + confetti!

참고: 자주 묻는 문제

증상원인해결
결제창이 안 열림 NEXT_PUBLIC_TOSS_CLIENT_KEY 미설정 .env.local에 키 추가 후 서버 재시작
결제 승인 실패 (500) TOSS_SECRET_KEY 미설정 .env.local에 시크릿 키 추가
"금액이 일치하지 않습니다" URL의 amount와 DB 주문 금액 불일치 정상 보안 기능. URL을 조작하지 않았는지 확인
결제 성공인데 포인트 0 payment_orders 테이블이 없음 DB 마이그레이션 2단계 재실행
CSP 오류 (콘솔) tosspayments 도메인 미허용 next.config.js CSP에 *.tosspayments.com 추가 확인
토스 SDK 로드 실패 패키지 미설치 npm install @tosspayments/tosspayments-sdk
