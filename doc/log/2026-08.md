### 2026-08-04 — 배경음악 재생 중 영구 정지 수정: 전환 실패 시 무음 고착 제거

- **원인 ①(주범, 실기 재현 완료):** `goToTrack`의 `startNew` 가 `el.volume = 0` 으로 놓고 `el.play().then(페이드인).catch(() => {})` — **play() 거부를 통째로 삼킨다.** 이 시점에 `activeIdx` 는 이미 스왑돼 해당 엘리먼트가 활성이므로, 볼륨 0 + 정지 상태로 남으면 timeupdate·ended·stalled 가 하나도 발생하지 않아 **자력 복구 경로가 전무**하다. UI 는 계속 "재생 중". `beginTrack` 경로는 `safePlay`(지수 백오프 재시도)를 타서 살아나지만 `startNew` 만 무방비였다.

- **원인 ②(전환 교착):** 딥(구곡 페이드아웃) 후의 신곡 시작을 `rampVolume` 의 **완료 콜백**에만 의존. 램프는 단일 `fadeTimer` 를 공유해 다른 페이드가 끼어들면 `clearFade()` 로 취소되는데, 그때 완료 콜백이 영영 실행되지 않아 `isTransitioning` 이 **true 로 고착** → `handleTimeUpdate`·`handleEnded` 가 모두 첫 줄에서 return → 프리로드도 다음 곡 전환도 불가 → 영구 정지. - **원인 ③(무음 구간):** 볼륨 램프 진행도를 **틱 횟수**로 계산 — 백그라운드 탭에서 setInterval 이 1초까지 throttle 되면 400ms 페이드인이 수십 초로 늘어나 그동안 사실상 무음.

### 2026-08-20 — 기록 시트에 % 입력 추가: 이북처럼 페이지를 모를 때도 진행 기록
- **카테고리:** #기록 #진행률 #이북 #백로그
- **중요도:** P1
- **지시:** `.backlog/0-inbox/_raw/기록기능 추가.md` — "기록의 페이지기록시 p숫자와 별도로 %도 입력할수있는 기능 / 이북으로 볼경우 원페이지를 모를경우가있기에 %로 업데이트". REQ-0008로 인테이크.
- **현황 파악:** 앱의 진행 축은 **정수 페이지 단일 기준**이고(`reading_logs.start_page/end_page`, `user_books.current_page`), %는 `lib/reading/progress.ts` 의 `computeProgressPercent()` 가 만드는 **출력 전용 파생값**이었다. 즉 %는 이미 있었지만 입력 경로가 없었다.
- **문제:** 이북 뷰어는 종이책 페이지 대신 %만 보여주는 경우가 많다. 그래서 페이지를 추측해 넣거나 0으로 두고 시간만 기록하게 되는데, 후자는 페이스 집계에서 `timeOnly` 로 빠져 **독서 속도 통계가 빈다.**
- **설계 결정 3건(사용자 확인):**
  - **저장 방식 = 환산 저장.** % 입력을 `round(total_pages × %/100)` 로 페이지 변환해 **기존 컬럼에 그대로** 넣는다. DB 마이그레이션 없음. 페이스·통계·공유·결산은 손대지 않는다. 대안이던 "% 원본 컬럼 추가"는 초/페이지 페이스부터 공유 카드까지 이중 단위 처리를 낳아 기각.
  - **`total_pages` 없는 책 = 총 페이지 먼저 입력 유도.** `%` 탭을 누르면 % 입력 대신 안내 + 기존 `TotalPagesEditor` 트리거를 노출하고, 저장되면 곧바로 % 입력이 열린다. "총 100p 가정"은 페이스 통계를 왜곡하므로 기각.
  - **범위 = 기록 시트 시작·끝 2곳만.** 사후 첨부·북마크 페이지·책 상세 진행률·독서속도 상세는 이번 범위 밖.
- **구현:** `percentToPage()` 를 `computeProgressPercent()` 와 **같은 파일에** 두어 진행률 환산의 단일 출처를 유지. p/% 전환 입력은 두 스텝이 공유하도록 `record-page-input.tsx` 한 곳에만 만들고, 저장 단위는 언제나 페이지로 정규화해 호출부(`onChange(page)`)는 % 존재를 모른다.
  - 끝 %가 시작 페이지보다 앞선 페이지로 환산되는 경우는 **막지 않고** 기존 저장 검증("끝 페이지는 시작 페이지 이상이어야 합니다")에 그대로 걸리게 뒀다 — 조용히 스냅시키면 사용자가 잘못 입력한 사실을 모른다.
  - 반올림 손실은 최대 0.5페이지, 왕복(57% → 182p → 57%) 안정.
- **검증:** tsc·eslint(변경 4파일 무경고)·`next build` 통과. **수동 UI 확인 3건(320p 책 % 입력 → 182p 저장 / 총 페이지 없는 책 유도 / `p` 탭 기본 유지)은 미실시 — 사용자 확인 필요.**
- **변경 파일:** `lib/reading/progress.ts`, `components/records/record-page-input.tsx`(신규), `components/records/record-start-step.tsx`, `components/records/record-end-step.tsx`.
