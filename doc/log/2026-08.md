### 2026-08-04 — 배경음악 재생 중 영구 정지 수정: 전환 실패 시 무음 고착 제거
- **카테고리:** #음악 #백색소음 #버그픽스
- **중요도:** P1
- **지시:** "음악 소리가 중간에 계속 재생되지 않고 끊기는 현상 — 최근 추가된 설정으로 발생한 것으로 보임. 점검 후 문제없이 재생되도록 업데이트."
- **증상 확인:** 사용자 확인 결과 "**재생 도중 완전히 멈춤(복구 안 됨)**", "**백색소음 채널에서 주로 발생**". 곡 전환 시 무음 갭이 아니라 영구 정지.
- **아닌 것부터 배제:** 음원 파일 107곡 전수 검사(ffprobe) — 메타 duration ↔ 실측 일치, VBR Xing/LAME 헤더 전부 존재(브라우저 duration 오판 없음). 프로덕션 CDN도 정상(`/music/*` 200, Content-Length 일치, Accept-Ranges·immutable). **파일·인코딩·배포는 무관.** 로컬 dev 실기 관찰에서도 자연 전환 6회 연속 정상 → 정상 경로에는 문제가 없고 **실패 경로에 복구 수단이 없는 것**이 원인.
- **원인 ①(주범, 실기 재현 완료):** `goToTrack`의 `startNew` 가 `el.volume = 0` 으로 놓고 `el.play().then(페이드인).catch(() => {})` — **play() 거부를 통째로 삼킨다.** 이 시점에 `activeIdx` 는 이미 스왑돼 해당 엘리먼트가 활성이므로, 볼륨 0 + 정지 상태로 남으면 timeupdate·ended·stalled 가 하나도 발생하지 않아 **자력 복구 경로가 전무**하다. UI 는 계속 "재생 중". `beginTrack` 경로는 `safePlay`(지수 백오프 재시도)를 타서 살아나지만 `startNew` 만 무방비였다.
  - **재현:** 프리로드 완료 후 스킵 시점의 play() 를 1회 거부시키자 구 코드는 **양쪽 엘리먼트 정지·볼륨 0 으로 25초+ 영구 무음**, 수정본은 **10ms 내 볼륨 복구 + 재생 재개**.
- **원인 ②(전환 교착):** 딥(구곡 페이드아웃) 후의 신곡 시작을 `rampVolume` 의 **완료 콜백**에만 의존. 램프는 단일 `fadeTimer` 를 공유해 다른 페이드가 끼어들면 `clearFade()` 로 취소되는데, 그때 완료 콜백이 영영 실행되지 않아 `isTransitioning` 이 **true 로 고착** → `handleTimeUpdate`·`handleEnded` 가 모두 첫 줄에서 return → 프리로드도 다음 곡 전환도 불가 → 영구 정지. (실경로: 프리로드 미완으로 대기 중이던 `beginTrack` 의 canplay 가 딥 도중 늦게 발화 → `startFadeIn` → `clearFade`.)
- **원인 ③(무음 구간):** 볼륨 램프 진행도를 **틱 횟수**로 계산 — 백그라운드 탭에서 setInterval 이 1초까지 throttle 되면 400ms 페이드인이 수십 초로 늘어나 그동안 사실상 무음.
- **백색소음에서 잦았던 이유:** 곡이 짧아 전환 횟수가 압도적이다. 모닥불 58초 = 시간당 62회 전환(음악 5분 곡의 5배). 전환마다 발동하는 결함이라 짧은 채널일수록 먼저·자주 드러난다.
- **수정(`music-mini-player.tsx` 단일 파일):**
  - `startNew` 의 play() 거부를 catch 에서 **볼륨 원복 + `safePlay` 재시도**로 인계(원인 ①).
  - 딥 후 전환을 볼륨 램프와 분리 — `scheduleAfterDip`(독립 setTimeout)로 예약해 **램프가 취소돼도 전환은 반드시 실행**(원인 ②).
  - `rampVolume` 진행도를 **경과 시간 기반**으로 전환 — 틱이 늦어도 페이드가 늘어지지 않는다(원인 ③).
  - **재생 워치독**(2s): 재생 중이어야 하는데 활성이 정지면 `safePlay`, 페이드 중이 아닌데 볼륨이 목표와 어긋나면 원복, 전환이 5초를 넘기면 `isTransitioning` 강제 해제. 원인 미상의 정지까지 덮는 최종 안전망.
