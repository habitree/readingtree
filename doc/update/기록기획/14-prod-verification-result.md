## 3. 잔여 이슈 (개발자 확인 필요)

### V5 캘린더 — ❌ 주의: 오늘 진행 기록이 홈 '독서 달력'에 미표시
- 홈 `독서 달력`은 **독서 활동일에 책 표지 썸네일/도트**를 렌더. 실측 결과 활동 표시일 = **2일·9일·10일**(표지/도트 있음).
- **오늘(15일) 셀에는 표지·도트·amber·카운트가 전혀 없음.** V2로 오늘 진행 기록(296p·270p)을 생성했음에도 캘린더에 반영되지 않음.
- 문서 V5 합격기준("진행 기록을 만든 날짜에 진행 표시/카운트가 잡힘")과 **불일치**. 문서가 경고한 `getDailyRecordsByType` dual-source 누락 패턴과 동일 증상으로 보임.
- 단, **홈 달력이 의도적으로 '진행'을 제외(시간세션/사진만 표기)** 하는 설계일 가능성도 있어, 우선 **개발자 확인** 권장. (진행 전용 amber 표기가 별도 화면에 있다면 위치 공유 필요.)

### V6 홈 스트릭/최근 진행 — ❓ 미확인: 해당 UI 부재
- 현재 홈에 **'연속/스트릭/일째' 카운터**와 **'최근 진행 체크' 카드**가 **존재하지 않음**(본문 텍스트·DOM 키워드 스캔에서 미발견. `이번 주 독서 현황`은 빠른 동작 버튼 묶음일 뿐). `/profile`도 계정 설정 화면으로 해당 카드 없음.
- 따라서 V6은 합/불 판정 불가. **문서의 전제(홈에 스트릭/최근 진행 카드 존재)와 실제 UI가 다름** → 기능 위치 또는 구현 여부를 개발자가 확인 필요.

### V9 모바일 — ⏭️ 미실시
- 본 브라우저 세션에서 창 리사이즈로도 뷰포트가 390px로 내려가지 않아(`window.innerWidth`가 1707 유지) 모바일 레이아웃을 강제 검증하지 못함. 데스크톱 폭에서 칩/그룹/카드 레이아웃은 정상.

1. **그대로 유지(롤백 불필요):** ③ 핵심 경로(진행→`reading_logs`, 피드/여정 반영)와 ①②④ 통합 피드가 모두 정상이며, **진행 기록 이중 표시/누락이 없음**. 따라서 `NEXT_PUBLIC_PROGRESS_IN_LOGS` / `NEXT_PUBLIC_UNIFIED_FEED` **플래그 OFF(롤백) 사유 없음**.

5. **V9 모바일:** 실제 모바일/모바일 에뮬레이션 환경에서 V3·V4 1회 재검증.

## 6. V5 수정 적용 (2026-06-15, 후속)

### 원인 (코드 진단)
- 홈 우측 **"독서 달력"** 은 `MonthlyBookCalendar` 컴포넌트이며, 데이터는 `app/actions/stats.ts` 의 **`getMonthlyBookActivities()`** 에서 옴.
- 이 함수는 진행 카운트(`noteTypes.progress`)와 책 표지를 **`notes` 테이블에서만** 집계함.
- 그런데 §11 ③ 백필 이후 **진행 기록은 `reading_logs` 로 이관**되어 `notes(type='progress')=0`. 따라서 진행만 있는 날짜(오늘처럼 시간세션 없이 진행만 기록한 날)는 **표지·진행 도트가 캘린더에서 누락**됨.
- 동일 캘린더 계열의 `getDailyRecordsByType()`·`getWeeklyProgress()` 에는 이미 `reading_logs` dual-source(`fetchProgressLogCreatedAts`)가 적용돼 있었으나, **`getMonthlyBookActivities()` 에만 누락**되어 있었음(이번 V5 증상의 직접 원인).
- 컴포넌트 렌더링은 정상: 진행 도트 색상(`bg-amber-400`)·진행 카운트 표시 로직이 이미 존재 → **데이터만 채우면 표시됨**.

### 수정 내용
- `app/actions/stats.ts` `getMonthlyBookActivities()` 의 `notes` 집계 직후에 **`reading_logs` 진행 기록 dual-source 병합** 추가(+52줄).
  - 필터: `reading_duration_seconds=0 AND image_url IS NULL AND end_page IS NOT NULL` (진행 기록 식별 규칙과 동일).
  - 해당 월(KST) 범위 내 진행 기록을 조회해 날짜별 `noteTypes.progress`/`total` 증가, `user_books→books` 조인으로 **책 표지(books[])도 함께 채움**(진행만 있는 날도 표지+amber 도트 표시).
  - **`isProgressInLogsEnabled()` 게이트**로 감쌈 → 플래그 OFF면 기존 동작 그대로(롤백 안전, 비파괴).
  - 레거시 `notes` 와 disjoint이므로 **이중 집계 없음**.
