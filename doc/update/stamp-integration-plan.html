Phase 2 통합 기획 · 2026.04.30

독서 기록 ↔ 스탬프 통합

"기록은 항상 남고, 사진을 더하면 스탬프가 된다."

어제 도입한 스탬프와 단순 시간 기록의 분리 문제를 해결. 기록을 먼저 저장 → 사진은 언제든 추가로 단일 멘탈 모델 구축.

1 통합 멘탈 모델

한 줄 정의 + 데이터 흐름

📝 기록
시간 / 페이지
→ 사진 추가
📮 스탬프
+ 사진 (승격됨)
둘 다 같은 reading_logs 1건. image_url이 채워지면 자동으로 "스탬프"로 분류돼 컬렉션 그리드에 노출됩니다.

2 확정된 사용자 결정 (3가지)

이 결정들이 기획의 토대입니다

① 통합 방식
B + C 하이브리드
기록은 항상 저장 + 사진은 나중에 첨부 가능 + 한 번에 풀 기록도 지원
② 자동 저장
유지 (30초+)
"그만 읽기" 시 자동 저장 → 이탈자 보호. 사후 사진 추가 흐름이 있어 의미 있는 기록이 됨
③ 포인트 정책
동일 적립
기록 1건마다 +Xp (사진 유무 무관). "매일 기록 = 포인트" 일관성

6 사용자 시나리오 (Before vs After 탭 수)

실제 사용자 경험이 얼마나 단순해지는가

1 "오늘 35분 읽었는데 사진은 안 찍었다"
3 결정 + 2 탭 다이얼로그 → "스탬프 vs 시간만" 결정 → "시간만" 클릭 → 저장
0~1 탭 다이얼로그 → "그만 읽기" (자동 저장) → 토스트만
2 "어제 35분 기록한 거에 오늘 사진 추가하고 싶다"
불가능 ❌ 흐름 자체가 없음
3 탭 책 상세 → 독서 시간 탭 → "📷 사진 추가" → 시트(attach) → 사진 선택 → 저장
3 "지금 다 읽고 사진+페이지+시간 모두 한 번에"
4 탭 다이얼로그 → "스탬프" → 시트 → 사진 → 페이지 → 시간 → 저장
3 탭 + 1 토글 다이얼로그 → "기록하기" → 시트 → 사진 토글 펼침 → 사진 → 저장
4 "음악 타이머 안 켜고 그냥 책 읽고 빠르게 기록"
3 탭 모바일 FAB(+) → 시트 → 페이지 입력 → 저장
3 탭 (동일) 동일하지만 시트 라벨이 "기록하기"로 변경 → "사진 없어도 OK"가 자명
5 "공유하고 싶다"
3+ 탭 책 상세 → 스탬프 그리드 → 카드 클릭 → 라이트박스 → 공유
1 탭 저장 직후 토스트의 "공유하기" 액션

7 진입점 정리 매트릭스

모든 기록 진입점이 일관된 라벨로 정리

위치 BEFORE (어제) AFTER (이번)
모바일 FAB(+) "스탬프 전용" — 메모/필사 진입점 사라짐 "기록하기" 시트 (사진은 옵션) — 메모도 가능
대시보드 모바일 퀵액션 "스탬프" 첫 칸 "기록" 으로 라벨 변경 (의미 통합)
사이드바 primary "스탬프" 액션 "기록하기" 로 라벨 변경
음악 타이머 다이얼로그 "스탬프 찍기" + "시간만 저장" 2버튼 "기록하기" 단일 CTA + "그만 읽기" 자동저장
책 상세 "독서 시간" 탭 표시만, 사후 첨부 불가 행마다 "📷 사진 추가" 인라인 칩
책 상세 "여정" 탭 표시만 행마다 "📷 사진 추가" 인라인 칩
토스트 (저장 후) 없음 "사진 추가" or "공유하기" 동적 액션

8 데이터 모델 변경 (최소)

마이그레이션 1개 (선택), 신규 액션 1개

마이그레이션 (선택적)

ALTER TABLE reading_logs
  ADD COLUMN IF NOT EXISTS promoted_at TIMESTAMPTZ;

-- 기존 사진 있는 행은 created_at 으로 백필
UPDATE reading_logs
   SET promoted_at = created_at
 WHERE image_url IS NOT NULL AND promoted_at IS NULL;

왜 필요한가: "어제 기록 → 오늘 사진 추가" 시 승격 시점 분리. 통계·정렬·정확도 향상. 단순 동작은 컬럼 없이도 가능 (선택적).

// app/actions/progress.ts
