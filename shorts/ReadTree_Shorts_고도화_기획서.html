1. 프로젝트 개요

목적

ReadTree(Next.js 16 + Supabase 독서 기록 플랫폼)의 브랜드 쇼츠를 자동 생산하여 인스타그램 릴스, 유튜브 쇼츠, 틱톡 등 SNS 채널에 주기적으로 업로드한다. 목표는 월 12~20편의 고품질 숏폼 콘텐츠를 월 $5 이하의 비용으로 생산하는 것이다.

Track B (추후): UGC 확장 - 사용자가 자신의 독서 기록으로 쇼츠 생성

1. 오늘의 문장 (DailyQuote) - 25초

인상 깊은 문장 한 줄과 책 정보를 소개하는 감성 쇼츠. 주 3~5회 발행.

Scene시간프레임내용컴포넌트
1. 오프닝0~3초0~90f로고 + "오늘의 문장" 타이틀Logo, SeriesTitle
2. 메인 문장3~15초90~450f워드 바이 워드 텍스트 등장TextReveal (word mode)
3. 책 정보15~20초450~600f표지 + 제목 + 저자BookCard
4. CTA20~25초600~750f앱 다운로드 유도CTAOverlay

4. 데이터 소싱 전략

문장 소싱 (DailyQuote)

notes 테이블에서 type='quote', is_public=true 조건으로 인기 문장을 추출합니다.

콘텐츠 점수 산정 로직

요소점수설명
길이 적절성1~10점20~100자 = 10점, 101~200자 = 5점, 그 외 = 1점
표지 유무0~5점표지 이미지 있으면 5점
최신성0~3점최근 7일 = 3점, 30일 = 2점, 그 외 = 0점
태그 풍부성0~2점태그 2개 이상 = 2점

Notes 테이블 구조 (참조)

interface Note {
  id: string;
  user_id: string;
  book_id: string | null;
  type: "quote" | "photo" | "memo" | "transcription" | "progress";
  content: string | null;
  page_number: string | null;
  is_public: boolean;
  tags: string[] | null;
  created_at: string;
}

책 소싱 (BookReview)

books 테이블과 user_books 테이블을 조인하여 status='completed'인 완독 수 기반으로 인기 책을 선별합니다.

shorts_queue 테이블 설계

CREATE TABLE shorts_queue (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  series TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending',
  -- pending -> scripted -> tts_done -> rendered -> published / failed
  input_data JSONB NOT NULL DEFAULT '{}',
  script_text TEXT,
  tts_audio_url TEXT,
  video_url TEXT,
  thumbnail_url TEXT,
  metadata JSONB,
  error_message TEXT,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- 같은 책 연속 노출 방지: 최근 사용 데이터 확인용 인덱스
CREATE INDEX idx_shorts_queue_series_status ON shorts_queue(series, status);
CREATE INDEX idx_shorts_queue_created ON shorts_queue(created_at DESC);

중복 방지 로직

같은 책이 연속으로 노출되지 않도록, shorts_queue에서 최근 7일간 사용된 book_id를 조회하여 제외합니다.

5. 파이프라인 아키텍처

6단계 파이프라인

Step 1: 데이터 소싱

Supabase에서 notes/books 데이터 조회 → 콘텐츠 점수 산정 → 최적 콘텐츠 선별

Step 2: AI 스크립트 생성

OpenAI gpt-4o-mini로 나레이션 스크립트 생성. Few-shot 프롬프트로 톤 일관성 유지.

Step 3: TTS 음성 생성

Edge TTS (ko-KR-SunHiNeural) 무료 음성 합성. 발음 사전으로 외래어 보정.

Step 4: Remotion 렌더링

Remotion 4.x로 1080x1920 세로 영상 렌더링. 오디오 오버레이 포함.

Step 5: 후처리

썸네일 자동 생성 (특정 프레임 추출), 메타데이터 (제목, 설명, 해시태그) 생성.

Step 6: 업로드

Supabase Storage에 업로드, shorts_queue 상태 업데이트.

OpenAI 스크립트 생성

모델용도비용/1K 토큰
gpt-4o-mini나레이션 스크립트Input: $0.00015, Output: $0.0006

1편당 약 200~500 토큰 사용. 월 20편 기준 ~$0.5~2.

Edge TTS 설정

설정값비고
음성ko-KR-SunHiNeural밝고 또렷한 한국어 여성
속도+0% (기본)필요시 조정 가능
비용$0완전 무료

스케줄링

GitHub Actions Cron으로 자동 실행:

# .github/workflows/shorts-daily.yml
name: Generate Daily Shorts
on:
  schedule:
    - cron: '0 6 * * 1,3,5'  # 월/수/금 15:00 KST (UTC+9)
  workflow_dispatch:

jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: cd shorts && npm ci
      - run: cd shorts && npm run generate:daily
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
          SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          SUPABASE_SERVICE_ROLE_KEY: ${{ secrets.SUPABASE_SERVICE_ROLE_KEY }}

6. 콘텐츠 타겟팅 전략

타겟 오디언스

세그먼트연령특성주요 관심사
핵심 타겟25~35세독서 습관화를 원하는 직장인독서 기록, 리뷰, 추천
확장 타겟20~40세인문/자기개발 관심 독서가감성 문구, 독서 팁

데이터 기반 선별

  • 인기 문장: 다수 사용자가 저장한 문장 우선 노출
  • 완독 수 높은 책: 검증된 인기 도서 리뷰 우선
  • 트렌드 태그: 최근 자주 사용되는 태그 기반 콘텐츠

같은 책 연속 노출 방지

최근 7일간 shorts_queue에서 사용된 book_id를 추출하여 selector의 exclude 목록에 전달합니다.

Phase 2: A/B 테스트 (추후)

  • 배경 컬러 변형 (forest vs paper 테마)
  • 애니메이션 스타일 변형 (word vs char reveal)
  • CTA 문구 변형
  • 성과 지표: 조회수, 좋아요, 저장, 앱 클릭

8. 검토 사항

저작권

  • 문장 인용은 200자 이내로 제한
  • 출처 (책 제목, 저자) 필수 명시
  • 고전/저작권 만료 작품 우선 활용 권장
  • 영리 목적 인용 시 공정 이용 범위 확인 필요

개인정보 보호

  • is_public=true인 기록만 활용
  • 사용자 닉네임, 프로필 정보 비노출
  • 추후 opt-in 설정 추가 (사용자 동의 기반)

표지 이미지

  • API(알라딘/네이버 등) 제공 표지 이미지의 2차 활용 약관 확인 필요
  • 대안: 표지 없이 책 제목 + 저자만 텍스트로 표시 (BookCover 컴포넌트 fallback)

Edge TTS 발음 이슈

  • 외래어, 책 제목, 저자명 발음 오류 가능성
  • 발음 사전 관리로 대응 (예: "카뮈" → 올바른 발음 표기)
  • TTS 품질 테스트 후 수용 가능 여부 판단 필요

품질 관리

  • OpenAI 스크립트: Few-shot 프롬프트로 톤 일관성 보장
  • 썸네일 자동 생성 후 수동 확인 프로세스
  • 생성된 쇼츠 큐에서 관리자 승인 후 발행 (Phase 2)

모니터링

  • 파이프라인 실패 시 Slack/Discord Webhook 알림
  • cost-tracker.ts로 API 비용 추적
  • shorts_queue.status = 'failed' 시 error_message 기록

9. 4단계 구현 로드맵

Phase 1 (2주) - 기반 구축 + DailyQuote 고도화

  • shorts/ 폴더 셋업 (package.json, config, types) 완료
  • DailyQuote 고도화 (브랜드 컬러, 실제 로고, 폰트 적용) 완료
  • 데이터 파이프라인 기반 (Supabase 연동, 셀렉터)
  • shorts_queue 테이블 생성 마이그레이션
  • Remotion 프리뷰로 결과 검증

Phase 2 (2주) - AI + TTS + BookReview

  • OpenAI 스크립트 생성 연동
  • Edge TTS 음성 생성 연동
  • BookReview 시리즈 구현
  • 전체 파이프라인 end-to-end 테스트
  • 비용 추적 시스템 가동

Phase 3 (2주) - 나머지 시리즈 + 운영 안정화

  • ReadingTip, BookVsBook, AppPreview 시리즈 구현
  • GitHub Actions Cron 자동화
  • 모니터링 알림 (Slack/Discord)
  • 품질 검수 프로세스 확립

Phase 4 (이후) - 확장

  • SNS 자동 업로드 (Instagram API, YouTube Data API)
  • 관리자 UI (쇼츠 큐 관리, 승인/거부)
  • A/B 테스트 프레임워크
  • UGC 확장 (Track B: 사용자 맞춤 쇼츠 생성)

10. 의사결정 체크리스트

  • 시리즈별 출시 우선순위 최종 확정

  • Noto Serif KR 폰트 파일 별도 다운로드 필요 (현재 NotoSansKR만 보유)
